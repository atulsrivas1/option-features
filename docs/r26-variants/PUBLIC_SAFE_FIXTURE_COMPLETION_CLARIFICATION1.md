# Fixture-completion proposals

2026-10-23. Coordinator-authored narrow proposal for fresh independent review. These items were found while authoring independent fixtures for the R26 variant contracts. Items 1 and 2 are proposed amendments (they choose between readings of the existing text); item 3 is a clarification. All earlier sealed R26 documents and the merged variant proposal (equity-features PR 629 and its clarifications) remain unchanged. No freeze, implementation or runtime approval follows.

## 1. Proposed amendment: group and span partition key

Boundary text describes a ParentOp as a one-contract partition, and the sealed original partitions by the admitted definition. Proposed: a flow group or span partition is one Scope and underlying/basis group, one contract, and the complete admitted economic definition of its executions: right, strike, expiry (a null `expiry_day` is a valid key value and equals another null) and multiplier. `integer_strike`, `eligibility` and `effective` are not part of the key. Executions sharing a `contract_id` but differing in a key field are different partitions and are not members of each other's parent window, repeated-price or multi-venue subset, or span population. An execution without an available admitted Definition has no definition fields, takes part in no definition-keyed partition and keeps its existing unavailable-definition handling. This is a membership change, not a restatement; it is consistent with the accepted cluster-partition correction ([equity-features issue 533 comment](https://github.com/atulsrivas1/equity-features/issues/533#issuecomment-6360812355); variant proposal [PR 629](https://github.com/atulsrivas1/equity-features/pull/629)).

Open points this proposal does not settle and which need fixtures and review before it enters a frozen handoff: whether group and span identifier preimages (the group preimage carries a parent anchor or subset start identifier; the span preimage carries an anchor identifier) are unambiguous across definitions, which depends on anchor identifiers being unique within an operation; and how per-contract `lane_prefix`/`capture` control coverage is expressed for definition-level partitions.

## 2. Proposed amendment: group reason when a member premium is overflow

Boundary text makes a summed parent-group overflow `premium_overflow` and ranks receipt reasons with `incomplete_capture` first, then `premium_overflow`, then `premium_unavailable`, but does not state a group's own reason when one member's premium is `premium_overflow`. Proposed: a group with a member whose premium is unavailable, including a member with `premium_overflow`, reports the group reason `premium_unavailable`, because a `GroupObject` carries no member Core. A group whose summed premium itself overflows still reports `premium_overflow`. A member's own reason stays preserved wherever the existing diagnostics rule (retain exact selected definition failure causes in member Core Metrics/Diagnostics) preserves it. A group containing a member with `incomplete_capture` keeps its existing handling and receipt priority. Note the tension with the reading that member overflow propagates as `premium_overflow`; this proposal chooses the conservative non-propagating reading.

## 3. Clarification: definition-basis mismatch pointer

An execution whose available Definition does not match the root's contract, scope, underlying, currency or bases, including `definition_basis_id`, is `identity_mismatch` at stage 6 at `/snapshot/executions/{e}/definition_use/definition_id`, where `{e}` is the actual execution index, using the first offending execution in snapshot array index order. This follows the existing missing-definition-id pointer and the same field-order rule.

## Not resolved here

`horizon_id` is the closed literal `full-session1` on BaselineOp, SessionFrame and ActivityKey, so a mismatch fails closed-record typing as a stage-3 `type_mismatch` at the `horizon_id` field path and no stage-6 pointer exists. The `observed_series` treatment of an incomplete selected common slot, and seven B3 snapshot pointers marked inferred in the private fixture packet, remain open gaps; fixtures carry no expectation for them until a reviewed clarification exists.
