## Exact operands and inclusive arithmetic

After structural admission, convert each finite source Decimal coefficient/exponent into an exact integer rational; never first convert S, K or quote price to float. Midpoint target p is exact rational `(bid+ask)/2`, constructed through integer rational arithmetic, unaffected by ambient Decimal precision. Binary64 r, q, supplied sigma, cap, tolerances and solver candidate sigma enter through their exact integer ratios. T is exactly `(fixing_ns-valuation_ns)/(365*86400*10^9)`. Retain original/converted operands as required by the boundary contract; approximate binary64 spot/strike/T are diagnostics and finite-representability checks, not operands redefining the certified model.

Construct each rational as `fmpq(n,d)` then its `arb` enclosure at the active precision. Integer rational construction is exact; rational-to-ball conversion encloses the represented real. Reconstruct the entire expression from original rationals at every precision tier. Do not increase precision on an already rounded result and pretend its original uncertainty disappeared. Constants 0, 1, 2 and signs are exact; pi, exp, log, sqrt and erfc are ball operations. Phi(x) is `erfc(-x/sqrt(2))/2`, avoiding the subtraction `1-erf(...)` for a negative tail. Evaluate d1, d2, A, B and the price/Greeks exactly as specified in MODEL_PROFILE using these operations. Dependency overestimation and cancellation can widen a ball; they never justify narrowing it by a point estimate.

For T>0,sigma>0, all mathematical denominators are strictly positive. The evaluated denominator ball must certify positivity before division; otherwise refine or fail. Price enclosure may be intersected with separately certified mathematical bounds L,U, but only by a reviewed exact interval intersection; never clamp an economic target or erase a nonempty uncertainty interval. Initially retain the unmodified equation enclosure to minimize implementation surface. Nonfinite/indeterminate balls never certify an ordering.

For a finite ball X, public `X.lower()` and `X.upper()` yield outward bounds as exact dyadic values. Extract exact integer mantissa/exponent with `man_exp`; do not parse the display string or convert bounds to binary64. Every subsequent comparison uses exact rational arithmetic. This gives an inclusive chain: original real operands -> balls -> outward dyadics -> outward persisted Decimals. Each inclusion and strict comparison is an explicit test obligation.

## Bounded precision, range and decimal certificates

Use exactly the increasing bit tiers `(128,256,512,1024,2048)`. Try the next tier only when the requested certificate is unresolved. Never call adaptive helpers with an unspecified maximum. Before transcendental calls, exact-rational checks require `abs(r*T)<=512`, `abs(q*T)<=512` and `sigma<=4096`; for d1/d2, enclosures must certify `abs(d1)<=1000000` and `abs(d2)<=1000000` before erfc. A failed or unresolved guard after the final tier returns `numerical_failure/precision_exhausted`. These are explicit initial implementation limits on mathematically valid inputs, not economic invalidity, a claim of full finite-real coverage or a restriction on negative rates. Record the guard/range in evidence and qualification fixtures. Endpoint symbolic paths bypass unnecessary interior operations.

Before exporting a dyadic endpoint, inspect its bounded mantissa/exponent without constructing an enormous denominator. A nonzero dyadic with binary magnitude below `2^-8192` can be enclosed outward using the decimal grid `10^-1024` (negative values analogously); a binary magnitude above `2^4096` fails `precision_exhausted`. Other endpoint rational expansions have bounded exponent size. Arb may internally represent tiny radii/exponents compactly; never expand an extreme native exponent into an unbounded Python integer/decimal string.

Persist bounds with at most 128 coefficient digits and exponent magnitude at most 1024 as required by BOUNDARY_CONTRACT. For a nonzero rational endpoint x in the permitted range, determine its decimal order k by bounded exact integer comparisons, choose grid exponent `e=max(-1024,k-126)`, and use integer floor(x/10^e) for a lower bound or integer ceiling for an upper bound. Form Decimal tuples exactly from that integer and e, without context-sensitive arithmetic. Zero is exact zero. A carry can require 128 digits; if coefficient/exponent/encoded-size limits still fail, return `precision_exhausted`. Trailing zeros are normalized only by exact tuple transformation. Outward rounding can widen uncertainty; acceptance always uses these actual persisted endpoints, not narrower internal balls. Tiny nonzero tails whose certificate cannot be represented accurately enough remain numerical failures; they do not become successful zeroes.

Fixed precision, bounded operand sizes, bounded guarded transcendental arguments, fixed expression size and finite solver evaluation counts bound admitted algorithmic work. ## Certified bounded IV

For admitted interior p and finite cap, V(sigma) is continuous and strictly increasing for finite sigma>0 because Vega=A*phi(d1)*sqrt(T)>0. This mathematical property licenses bracketing; a numerically rounded zero Vega does not negate it. Starting lo=0 and hi=cap, certify V(lo)<=p<=V(hi) using exact endpoint proofs/enclosures. V(cap).high<p proves `bracket_exceeded`; an unresolved cap comparison is refined and otherwise `bound_precision`. A proved exact cap root is retained as [cap,cap]; ordinary rounded equality is insufficient.

Bracket sigma endpoints/candidates are finite binary64 values interpreted as exact dyadics. Form the mathematical midpoint rational then round to nearest binary64 with ties to even using a reviewed bounded conversion. Require lo<c<hi except for an already certified endpoint solution. A side is discarded only after its strict price ordering is certified: V(c).high<p sets lo=c; V(c).low>p sets hi=c. Enclosure overlap first triggers higher precision, never a guessed sign.

If the midpoint still overlaps at 2048 bits and the convergence tests below do not pass, evaluate two representable interior probes nearest `(lo+c)/2` and `(c+hi)/2`, with the same full refinement policy. If their certified signs bracket p, replace the interval by those probes. Otherwise keep the original bracket and return `bound_precision`; never discard a side whose ordering was not proved. This handles an exact or almost exact midpoint root without pretending a zero-width result. A probe that rounds onto an endpoint/candidate cannot certify progress; absent successful convergence it yields `precision_exhausted`.

One solver iteration means one midpoint decision, including up to two rescue probes. A price evaluation attempts at most five tiers; each iteration therefore permits at most 15 fixed-expression evaluations, plus at most 15 terminal candidate evaluations and 15 initial endpoint/bound evaluations per solve. Total is at most `15*(max_iterations+2)`; defaults/caps remain those in MODEL_PROFILE and request limits. Analytic endpoint checks do not consume iterations. A decision that contracts the bracket consumes one iteration. Exhausting max_iterations without convergence yields `iteration_limit`; inability to resolve a required comparison or make representable progress yields the reason specified above. No unbounded Newton loop, automatic precision doubling beyond 2048, callback or per-iteration cancellation is introduced.

Candidate c must lie in the current certified bracket. Using its persisted price enclosure [a,b], compute exact rational R=max(abs(a-p),abs(b-p)). Convert the configured binary64 tolerances to exact rationals. Accept only if BOTH R<=price_abs_tol+price_rel_tol*abs(p) AND hi-lo<=vol_abs_tol+vol_rel_tol*abs(c), with exact arithmetic for both tests. Persist R as exact Decimal only when its exact finite decimal fits existing scalar bounds; if it does not fit, return `precision_exhausted`, never round it down. Exact p=L returns sigma0 through the separately proved endpoint rule. Record actual enclosure method, final bracket, candidate, iterations, target, tolerance configuration and conditioning evidence. Ill-conditioning does not waive either test.

## Forward values, context and independent acceptance

Forward-model point values and diagnostic candidate prices are binary64 approximations accompanied by persisted enclosures where the contract supplies them. Obtain a candidate by reviewed nearest-even conversion of the exact rational midpoint of persisted endpoints; reject nonfinite conversion. Interpret the binary64 candidate as its exact dyadic rational c64 and compute exact E=max(abs(c64-a),abs(c64-b)) against the actual persisted endpoints. A forward available value must satisfy E<=`1e-12*max(abs(a),abs(b))` in exact rational arithmetic in its canonical unit, or be a symbolically proved exact zero. No binary64-rounded subtraction may decide this certificate. This conservative initial relative certificate prevents successful zero for a nonzero tail. An interval straddling zero usually requires refinement; unresolved cases fail rather than claiming accuracy. Independent fixture-specific budgets may be tighter; satisfying this certificate alone is not fixture acceptance. Greek formulas use the same operand/enclosure path, with per-output failure and explicit endpoint behavior.

All calls using flint context are serialized by one process-wide numerical owner, including direct calculation callers. An evaluation uses an exception-safe exclusive context guard, sets only bounded work precision and `ctx.threads=1`, and restores the previous settings on every exit. No callbacks execute while the context is held; no concurrent foreign flint-context mutation is admitted. Fail a reentrant attempt explicitly. Thread safety is not inferred from native Arb claims or the Python GIL. Qualified R25 workers remain one active whole-request task; a future parallel API requires a new reviewed context/resource design. The implementation must document this context-owned library restriction and test restoration after failures. No cleanup call mutates native caches during another operation.
