# EQ182 independent fixture protocol

This is source-only fixture design for [EQ182](https://github.com/atulsrivas1/equity-features/issues/527). [INDEPENDENT_FIXTURES.json](INDEPENDENT_FIXTURES.json) contains manually derived rational expectations, analytic expressions and semantic cases. No generator, numerical function, build, import, database or test has been executed for this packet. Nothing here establishes numerical acceptance, a contract freeze or implementation admission.

The result vocabulary follows the contemporaneous EQ182 canonical draft: available, missing_input, ineligible_input, invalid_input, unsupported_profile, not_applicable, undefined, nonidentifiable_inverse, bracket_exceeded, iteration_limit and numerical_failure. Available results use reason `ok`. Remaining reasons must follow the reviewed model/boundary contract; missing civil binding currently proposes `missing_civil_binding`. The coordinator must reconcile exception-versus-result boundaries and precedence before making executable fixtures. Available zero is a value, with supplied/computed origin recorded separately. Diagnostic model time, transport quantities and unit projections are probes rather than extra matrix features or initial API output IDs. Canonical model price is `pricing.price`.

## Operand provenance and exact cases

Every operand is original synthetic data. The common fixture provenance is a design template; later wire fixtures must provide actual explicit definition, event/effective/known-at and cutoff fields. String placeholders are not admissible runtime records. Validate each reference's point-in-time eligibility before calculating. No wall-clock, latest-definition lookup, future revision or implicit timezone binding may fill an absent operand. Pair option and underlying identities explicitly; neither relabelling an option quantity as shares nor collapsing instrument identities is allowed.

Rational strings express exact mathematics, not rounded binary floats. Model time uses exact integer nanoseconds and a 365-day denominator. A synthetic certified civil ordinal difference is separate from model time. Prices and Greeks are per underlying payoff unit; a declared multiplier is applied exactly once only to named contract/position projections. The supplied signed-delta fixture tests the inventory's absolute-delta projection without treating the supplied producer's model as BSM. Supplied gamma remains independently ready when model pricing operands are absent.

Quote coverage uses the frozen expected sample population for one contract and window. Deduplicate sample identities, require eligible observations to belong to that population and bind the eligibility policy to the request. Extra observations cannot increase coverage. Missing population evidence cannot become observed zero. A known nonempty population with zero eligible samples is available zero; an empty denominator is undefined. This sample-count ratio is neither time coverage nor chain completeness. Chain completeness requires its own metadata.

The coordinator proposes the original `option-chain-breadth1` score for independent contract review: 100*A/N, with N the distinct frozen expected contract count and A the distinct members having an eligible positive-quantity trade in [start,end) and an eligible current quote at valuation. Certified complete trade and quote source coverage for the entire population/window is mandatory. The proposed fixtures yield25 for A1/N4, observed0 for A0/N4 under complete coverage, ineligible_input/incomplete_source for partial coverage and undefined/empty_population for an empty denominator. Causal filtering and member deduplication precede A selection; exact duplicate source identities are atomic boundary errors, not silently deduplicated input records. Cancelled/revised trade histories require dedicated later fixtures. This is a new named formula, with no claimed reproduction of a private score. The proposal is not frozen or accepted by inclusion in this design.

The smooth analytic put case uses S=K=100, r=q=0, sigma=2, T=1. Then d1=1 and d2=-1, so put price is 100(2 Phi(1)-1), signed delta Phi(1)-1, absolute delta 1-Phi(1), and gamma phi(1)/200. These are independently reduced mathematical expressions. They have not been evaluated into accepted decimal literals. The companion IV cap expression proves a mathematical root at2 exceeds a configured cap1; an executable decimal quote must later preserve a clear error margin relative to cap-price and bound tolerances.

## Later numerical qualification

After the resource window and reviewed contracts permit execution, author a separate high-precision oracle generator using an independently implemented normal CDF/density and documented arbitrary-precision dependencies. Do not import production option pricing, IV or projection functions into the oracle. Record generator source commit, dependency versions, precision/rounding settings, input rational encodings, output decimal literals and a content digest. Generate at two substantially different precisions; retain the higher-precision result only after the retained digits agree within a predeclared oracle budget. Independently review the mathematics and generator source. A precision check alone does not prove that a shared formula is correct.

Check interior call and put outputs against put-call parity, derivative identities and independently evaluated finite-difference derivatives at multiple step sizes. Include nonzero positive/negative r and q, short/long positive T, small/large volatility and deep in/out-of-the-money cases within the admitted domain. Keep derivative probes away from nondifferentiable limits, and justify truncation/rounding bounds rather than treating one finite-difference step as truth. Exact T0 and sigma0 cases use the separately frozen per-output limit rules, including undefined kinks; do not approximate them with tiny positive parameters.

For IV, construct independent high-precision target prices at known sigma and compare the returned root, residual and final bracket to the frozen error budgets. Production price-to-production-IV round trips are useful integration checks but are not independent correctness evidence. Test exact lower and upper bounds, just-outside bounds, bounded-cap exhaustion, iteration exhaustion, tiny-vega conditioning and numerical-domain failures. Freeze tolerances before looking at implementation failures. There must be no accepted numeric root solely because residual is small when the required bracket uncertainty fails.

Turn each semantic fixture into complete wire records using the reviewed schema. Add isolated fixtures for one-sided/stale/future quotes, unsupported exercise/deliverables, contradictory units/civil bindings, malformed configuration and relevant precedence. Never combine unrelated faults in the only test of a reason. Record whether malformed records raise a boundary error or valid records return per-output unavailable status. An unavailable output has null numeric value; no NaN/sentinel masquerades as an available value. Independent-ready outputs must remain available in mixed requests.

## Evidence and acceptance

Numerical goldens become eligible only after independent source review and executed local validation identify the exact tested commit, command, environment and result. A Windows local run does not establish Linux validation. Hosted CI is optional and is not merge proof required by the owner. Resource reservations and unrelated release ownership remain protected.

Direct library, worker and stored-readback runs must agree on value, status, reason, quality/coverage, origin, units, causal evidence and identity under the declared tolerance contract. Retry tests preserve identity for equal content and conflict for changed content. Actual computed/stored browser demonstration belongs to release integration; this source packet is not that demonstration. Preserve expected-value provenance and review receipts beside executed evidence; do not mark design cases passed merely because their JSON parses.
