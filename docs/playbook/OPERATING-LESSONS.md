# Operating lessons: what went wrong or nearly did, and how we handle it

> Working document, not a decision. Part of the portable playbook (`playbook/README.md`). Each row: what happened, the cost, the rule that now prevents it. Some rows cite WatchYourList facts as examples; replace them on copy. Rows 4 and 5 rest on the owner's and coordinator's account, not on a repo record.

| # | What happened | What it cost | What we do now |
|---|---|---|---|
| 1 | **A separate session merged boards without the gate.** Separate design sessions drew and merged several boards before the three-review gate existed on main (example: 13 boards). | No independent UI or architecture review on them; the owner had to rule on retroactive reviews (he skipped them and chose review-as-built). | Tell every session the rules in its first prompt (`TEMPLATES/agent-prompts.md` standing lines). Land the gate on main before starting parallel sessions. The gate is in the PR template and the charter; check the Review table before any merge. **Suggested default (not an owner agreement):** enforce it with branch protection (`VARIANTS.md`). |
| 2 | **Several agents shared one checkout.** Several agents worked in one shared checkout. | Risk of overwritten edits and wrong-branch commits; the owner ruled one worktree per agent. | One git worktree per agent, outside the repo: `git worktree add <path> origin/main -b <branch>`; two worktrees cannot hold the same branch; remove with `git worktree remove <path>` when done. Never edit the shared checkout. |
| 3 | **The GitHub login flipped accounts.** The CLI login switched to the other account between sessions. | Risk of pushes and PRs on the wrong account; the owner made the switch a standing first step. | Run `gh auth switch -u <account>` before every git or gh call, in every prompt. **`gh auth switch` is global to the machine: all sessions share it, so one session can flip another's account.** Check `gh auth status` immediately before a push, or give each session its own `GH_TOKEN`. |
| 4 | **Stacked PR plus squash merge.** A PR was built on another PR's branch; the base was squash-merged, so main holds one new commit while the stacked branch still carries the base's original commits. | The same changes appear twice and conflict across the same files; main is not a clean ancestor of the branch. | Retarget the stacked PR to main before the base merges, or after it merges run `git rebase --onto origin/main <old-base-tip> <branch>` (replays only the stacked commits). Avoid stacking; or merge the base with a merge commit. |
| 5 | **Whole-file line-ending rewrites.** An agent rewrote whole files with different line endings. | Every line shows as changed; reviews become unreadable and merges conflict. | Check the repo's majority (`git ls-files --eol`), preserve per file, compare blobs against main, and check `git diff --stat --ignore-space-at-eol` before pushing. Durable fix: a `.gitattributes` with `eol` rules and a deliberate `core.autocrlf` setting on Windows machines. Say "line endings per file unchanged" in the changelog. |
| 6 | **Generated files were hand-merged.** Backlog, coverage and package manifests merged by hand at conflict time. | Silent drift between generated files and their sources. | Take main's version, then regenerate with the script; the `--check` mode fails when stale; never edit a generated file by hand. |
| 7 | **Decision-number collisions.** Parallel authors took the same next id; some ids were reserved in other files but not yet in the log. | Renumbering across documents; broken references. | Reserve id ranges per author, grep the whole repo (contracts too) for the highest and reserved ids before choosing, renumber the later PR only. See `DECISIONS-PROCESS.md`. |
| 8 | **Review rounds find real defects.** Reviews of documents and contracts reverted dozens of "Ready" stories, found stale markers, a hidden missing file and a parser bug in a generator (example: 28 stories reverted). | "Ready" was over-stated. | Budget two review rounds per PR. A fix-round agent fixes; the same reviewer re-checks. Never relax a review to save time. "Honest Ready": a stub that lists the needed shape as open does not satisfy Ready. |
| 9 | **Counts drifted across documents.** Story, board and decision counts typed by hand disagreed. | Readers could not trust any number. | Generate counts and indexes with scripts; a sync check fails on new drift against a baseline; documents cite the generated file instead of copying numbers; never add to the baseline to hide drift. |
| 10 | **Reviewing the author's claims without a runtime.** Some sessions could not render the product or run the app, so reviews risked repeating the author's summary (example: no way to render boards until a throwaway renderer was built). | "Verified" claims with nothing behind them. | Reviewers verify against files, scripts and the running app, not the summary; write "Not verified: <what>" honestly; build a render or run path early; the PO decides whether to accept with a stated limit. |
| 11 | **Cost.** Idle agents and whole-repo reads burned tokens. | Owner concern; usage limits hit. | Idle roles do not run; scoped reviews; cheaper model for mechanical work; Researcher cap; pause and resume at a usage limit; no retry loops. |
| 12 | **Context rotation.** A long coordinator chat lost track of state. | Re-deriving what was Done and what was in review. | A short `HANDOFF.md` updated after each merge: Done, in review, Ready buffer, open owner and human-only items, next steps. Rotate the session before it is heavy (suggested trigger: a turn or token count you choose). |
| 13 | **Independent verification before merge catches what the author and the reviewers' summaries miss.** | Reviews of documents and contracts found defects the authors' own summaries did not mention (row 8). | Before a risky merge the coordinator reads the diff for real (not the file list), re-runs every check in a fresh worktree, and spot-checks one claim per review. A fresh independent reviewer for every PR, including documents. |
| 14 | **Drift from the agreement** (example from another team of the owner's). A session started giving shallow reviews of big document PRs and skipped the retrospective. | The owner had to point it out. | Coordinator follows the agreement fully: real diff reads, an independent reviewer on every PR including docs, retire finished workers (no reuse across releases), manual browser test, owner demo, retrospective after each release (the last was that team's agreement). |
| 15 | **Owner questions buried in long reports.** | The owner missed decisions. | One question at a time with selectable answers; short replies; non-blocking items go in the release report. |

## Quick pre-merge checklist (coordinator)

- [ ] Review table complete (UI, architecture, code), N/A each with a reason
- [ ] No open "changes" verdict without the reviewer seeing the fix
- [ ] Tester results table present (for story PRs), severity noted, no blocking defect open
- [ ] PO accept recorded
- [ ] Every check in `AGENTS.md` run on the merged state, generated files regenerated
- [ ] Line endings preserved; decision ids unique and in range
- [ ] Changelog entry with Verified and Not verified
- [ ] Not pushed to main; merged by the coordinator
- [ ] `HANDOFF.md` updated
