## 1. Closed additive family

Keep the existing three repositories and all four released R25 distributions completely untouched. Add four **new optional distributions**, each proposed `0.1.0a1`: `option-flow-contracts` / import `option_flow_contracts` in library-repository `packages/flow-contracts`; `option-flow-features` / import `option_flow_features` in library `packages/flow-features`; `option-flow-io` / import `option_flow_io` in I/O-repository `packages/flow-io`; `option-flow-workers` / import `option_flow_workers` in worker-repository `packages/flow-workers`. Public functions/classes defined here are exported by their corresponding new import packages; internal module organization does not add old runtime imports. Calculation depends only on exact `option-flow-contracts==0.1.0a1`; I/O additionally depends on `duckdb==1.5.6`; workers depend on all three new own distributions at exact0.1.0a1. No flint or R25 runtime dependency. The separate flow verifier admits exactly these four plus DuckDB, never a mixed old/new cohort.

**Superseded packaging proposal:** initially bumping the existing four distributions to0.2.0a1 was rejected before freeze. Actual R25 evaluator output embeds its0.1.0a1 package identities; replacing installed package metadata while preserving those bytes would misreport provenance, and flow-only exact arithmetic would unnecessarily inherit flint. Separate optional distributions preserve truthful new package metadata and every old source file, package manifest/version, entry point, verifier, wheel/sdist artifact and R25 result byte. Retained R25 regression runs in its original six-distribution cohort; it is not claimed executable under the new five-distribution flow cohort. New flow record package-version literals refer to the new named flow distributions even though their numeric version is also0.1.0a1. New flows never deserialize through R25 entry points. Candidate future GitHub tag is `flow-v0.1.0a1` to avoid the published R25 tag; this document does not authorize publication.

New schema identities are `option-flow-canonical1`, `option-flow-request1`, `option-flow-result1`, `option-flow-checkpoint1`, `option-flow-json1`, `option-flow-record1`, `option-flow-work1`, `option-flow-generation1`, `option-flow-cohort1`. Formula identity is `option-flow-formulas1`; policy identity is `r26-flow-policy1`. Package versions, formulas, schemas, datasets and artifact identities remain distinct.

All declarations below are closed exact fields in listed constructor order; every record is a frozen slotted dataclass. Collections are tuples in Python and arrays in JSON. Optional fields are present with null, never omitted. No extra field, subclass, arbitrary dictionary, float, bool-as-int, callback, dynamic class import or object deserialization is admitted. `s` means ASCII identifier matching `[A-Za-z0-9][A-Za-z0-9_.:/-]{0,127}`; descriptions/rights references use `t`: nonempty Unicode scalar text, NFC, no Unicode categories Cc/Cf/Cs, at most 1024 UTF-8 bytes. Currency `c` is `[A-Z]{3}`. Hash `h` is 64 lowercase hex characters. `n` is exact int 0..2**63-1; `i` is exact signed int of at most 128 decimal digits; `d` is finite exact Decimal, at most 38 significant digits, scale at most 18, magnitude <10**38. Decimal inputs must be nonnegative unless explicitly stated otherwise. `b` is exact bool. `?X` permits null. No implicit conversion is performed by pure contracts.

Decimals serialize in fixed notation, no plus/exponent/trailing fractional zeros, no leading zeros except `0`, no negative zero. Rational `q` is `FlowRational(numerator: int, denominator: int)`; denominator positive, gcd(abs(numerator),denominator)=1, zero exactly 0/1; both have at most 256 decimal digits. Wire rational components are canonical signed/positive integer **strings** (`0|-?[1-9][0-9]*`, denominator `[1-9][0-9]*`); timestamps/counts remain JSON integer numbers. Decimal reconstruction must be context independent from sign/digit/exponent tuples. Rational and integer calculations are exact; no conversion through binary float or ambient Decimal division.

## 2. Admission limits and deterministic failures

The fixed `FlowLimits` fields and maximum accepted values are:

| Field | Maximum/default |
| --- | --- |
| max_wire_bytes | 16777216 per envelope/canonical value |
| max_records | 100000 total records recursively, including baseline members and checkpoint history |
| max_groups | 128 |
| max_streams | 128 |
| max_baselines_per_group | 32 |
| max_outputs | 64 |
| max_result_rows | 8192 |
| max_replay_cuts | 128 |
| max_integer_digits | 256 for every arithmetic intermediate and exact result |

Each field is an exact positive int and may be lowered; raising a limit fails `resource_limit`. A checkpoint plus suffix shares these limits; restoring does not create a second unaccounted budget. Array elements/string lengths/decimal tuple lengths are checked before expansion/large-integer arithmetic. Cross-multiply/add/multiply operations precheck conservative digit bounds then check actual result; do not allocate a huge integer to discover its size. All intermediate arithmetic (including gcd inputs, squared shares, median sums, products) must fit 256 digits; otherwise raise `FlowValidationError('resource_limit', path)` before any publication. No rounded fallback. Result encoding is preflighted before publication. A conservative rejection at the specified bound is allowed only when the documented digit inequality necessarily exceeds the bound; no approximate/implementation-specific safety margin may change admitted mathematical inputs.

Admission order, including error priority, is: (1) byte count/UTF-8/token depth, (2) envelope keys/version/digest shape, (3) duplicate JSON keys/noncanonical scalar/record shape/types in declaration order and array index order, (4) local bounds/scalar constraints, (5) collection uniqueness/identity/references, (6) correction graph and stream causality, (7) request/population/baseline compatibility, (8) numerical evaluation and output coherence. Within a stage use record declaration order below and lexicographic identity order, never hash-map iteration. JSON scanning rejects duplicate keys before digest checking; syntax errors use `invalid_json`, invalid UTF-8 `invalid_utf8`, unsupported version `unsupported_schema`, extra/missing fields `field_set`, wrong exact type `type_mismatch`, invalid scalar `invalid_scalar`, duplicate identities `identity_conflict`, missing referenced ID `missing_identity`, invalid correction `invalid_correction`, incompatible structural identity `identity_mismatch`, digest mismatch `digest_mismatch`, noncanonical bytes `noncanonical`, limit violation `resource_limit`. Exceptions carry stable `code` and JSON-pointer `path`; message text is not normative. Type/shape/causal conflicts are exceptions, never fabricated numerical results.

Precision/count/byte ceilings (19 fractional digits,39 significant digits,129 input integer digits,257 intermediate digits) are `resource_limit`; invalid sign/zero quantity/nonpositive multiplier/out-of-range ns are `invalid_scalar`. A finite Decimal object with redundant trailing zeros is normalized without value change by canonicalization, whereas equivalent noncanonical **wire strings** are rejected `noncanonical`. Malformed Decimal string syntax is `invalid_scalar`; no float parsing fallback. Knowledge ties along a revision chain are allowed when positions strictly increase; known_at regression is `invalid_correction`. At stage3 extra/missing keys are reported before scalar decoding; duplicate JSON keys have field_set at their first duplicate key pointer.

## 3. Immutable supplied facts

Record names in backticks are codec type names. These tables specify all fields, not examples. `[]X` denotes tuple of X. All `input_binding_id` references resolve to this snapshot's bindings. Every ID is `s` unless explicitly typed. Every fact has its own binding; distinct synthetic and observed facts never share a falsely labelled source binding.

`FlowBinding` (`flow_binding`): `binding_id:s, source_id:s, source_revision:s, source_content_sha256:h, provenance_mode:synthetic|licensed|public_permitted, rights_reference:t`. Same field meaning as R25 InputBinding but a separately closed flow type; explicit conversion may preserve economic facts, never claim equal domain hashes.

`FlowReference` (`flow_reference`): `reference_id:s, contract_id:s, underlying_id:s, currency:c, action_basis_id:s, right:call|put, strike:d, multiplier:d, expiry_ordinal:n, civil_ordinal:?n, civil_instant_ns:?n, civil_known_at_ns:?n, calendar_id:?s, calendar_revision:?s, spot:?d, spot_event_ns:?n, spot_known_at_ns:?n, spot_stream_id:?s, spot_position:?n, effective_from_ns:n, effective_to_ns:?n, known_at_ns:n, revision_id:s, input_binding_id:s`. Strike/multiplier strictly positive, spot if present strictly positive. Ordinals are 1..3652059. Effective interval is half-open, nonempty; null end means open. Optional spot's five fields are either all null or all nonnull; optional civil's five fields likewise. Missing civil/spot never removes the admitted positive multiplier/right/strike or blocks independent totals. Calendar fields attest the supplied conversion; kernel does not read timezone databases. Civil instant if supplied must equal the root execution's economic event_ns wherever this reference is used. Effective interval must contain the root event instant. Definition/currency/action/right/strike/multiplier/expiry cannot change within a correction chain; a changed corporate-action deliverable requires a new contract identity. Non-scalar deliverables are not represented by this profile. Historical reference context comes from the root new execution's reference_id and is admitted at its original signing boundary; a late replacement reference cannot silently introduce future civil/spot facts. Every new execution root must reference a definition known_at_ns<=its original signing_boundary_ns A; otherwise snapshot semantic admission fails identity_mismatch at /snapshot/executions/{actual_index}/reference_id, before evaluation, including retained context seeds. Unreferenced future definitions remain permitted. A later replacement reference cannot substitute for an inadmissible original root definition.

`FlowExecution` (`flow_execution`): `execution_id:s, revision_id:s, kind:new|cancel|replace, target_execution_id:?s, target_revision_id:?s, contract_id:s, session_id:s, stream_id:s, position:n, event_ns:n, signing_boundary_ns:n, known_at_ns:n, price:?d, quantity:?i, condition:regular|excluded, venue_id:?s, observed_side:buy|sell|unknown, observed_side_semantics_id:?s, observed_side_known_at_ns:?n, reference_id:s, input_binding_id:s`. New/replace require price>=0 and integer quantity>0. Cancel requires price/quantity null, condition excluded and observed_side unknown. Signing boundary A>=event_ns and new root known_at<=A. Observed side semantics and known-at are both null (missing source, side must unknown) or both nonnull; they describe supplied classification, not economic aggressor truth. New requires both targets null; cancel/replace require both nonnull. Correction targets identify an earlier revision in the same contract+session+stream. `execution_id` is stable economic root ID throughout its chain, `revision_id` unique per root. New's execution_id must equal target_execution_id on all its corrections. Cancel/replace event_ns, signing_boundary_ns and session_id equal the root's immutable values; position/known_at describe publication of the revision, not a newly invented execution time. A cancel is terminal; resurrection uses a new economic root ID. Replace may target new or latest replace, never a cancel or an already superseded revision. Source positions of new roots have nondecreasing event_ns within session+stream; known-at/correction positions give independent revision visibility.

`FlowQuote` (`flow_quote`): `quote_id:s, revision_id:s, kind:new|cancel|replace, target_quote_id:?s, target_revision_id:?s, contract_id:s, stream_id:s, position:n, event_ns:n, known_at_ns:n, bid:?d, ask:?d, condition:regular|excluded, input_binding_id:s`. New/replace permit independently null bid/ask; present sides >=0. Cancel requires both null and condition excluded. New targets null; corrections target latest active earlier revision of the same quote_id/contract/stream and preserve root event_ns. Crossed, locked or one-sided quotes are economic eligibility facts, not structural errors. No quote side or ordering fact is synthesized from the trade price.

`FlowGroup` (`flow_group`): `group_id:s, kind:underlying|contract|right|expiry, underlying_id:s, contract_ids:[]s, right:?call|put, expiry_ordinal:?n, currency:c, action_basis_id:s`. Contract IDs nonempty, sorted/unique; kind contract requires exactly one; kind right requires right nonnull and expiry null; kind expiry requires expiry nonnull and right null; underlying/contract require both null. All member references must agree with group restrictions, currency/action and underlying. No cross-currency sum. Groups may overlap; each output is independently identified by group_id.

`FlowPopulation` (`flow_population`): `population_id:s, group_id:s, window_start_ns:n, window_end_ns:n, expected_contract_ids:[]s, expected_execution_ids:[]s, expected_quote_ids:[]s, complete:b, known_at_ns:n, input_binding_id:s`. Window nonempty. Member IDs are sorted/unique. Execution/quote IDs are economic root IDs, not revision IDs. Expected contract IDs exactly equal group's contract_ids. A complete certificate is a supplied assertion of full source membership; kernel checks identity/count/clock coherence, not external truth. An absent/incomplete/future certificate is not zero. Every active admitted execution in the group/window must be listed; no silent subset. All listed execution roots must be present in the supplied ledger, including canceled/excluded roots; expected quote IDs define the admitted supplied quote population over the request's seed+window interval. Completeness of trade membership does not guarantee a causal usable quote for every execution.

`FlowContextCertificate` (`flow_context_certificate`): `certificate_id:s, kind:execution_prefix|quote_prefix, contract_id:s, session_id:s, stream_id:s, session_start_ns:n, through_position:n, expected_root_ids:[]s, complete:b, known_at_ns:n, input_binding_id:s`. IDs sorted/unique; session_start<=every covered root event and through_position covers all listed root positions. A target's context requires complete certificate of the matching kind/contract/session/stream, known_at<=A, through_position>=target root position, with exact retained covered membership from session start through that position; no omitted referenced root/revision ancestor. Multiple applicable certificates must agree in covered membership or fail identity_conflict; choose smallest through_position then certificate_id for deterministic dependency identity. This is an explicit supplied assertion, not provider completeness proof. Missing/incomplete/future context certificate makes sign unknown (`tick_seed_unavailable` or `quote_missing`) while unsigned population totals remain independently available. Output-window completeness never substitutes for prior context completeness. Quote roots infer session from the certificate; one quote root cannot belong to contradictory session certificates.

`FlowBaseline` (`flow_baseline`): `baseline_id:s, group_id:s, slot_id:s, session_ordinal:n, horizon_id:s, window_start_ns:n, window_end_ns:n, known_at_ns:n, policy_sha256:h, population_sha256:h, currency:c, action_basis_id:s, contracts:?q, trade_count:?q, premium:?q, member_record_sha256s:[]h, complete:b, input_binding_id:s`. Ordinal range as above; window nonempty, present values nonnegative and contracts/trade_count denominator1. Members sorted/unique; complete empty baseline has empty members and present metrics zero; a null metric is unavailable, not zero. The binding and population digest attest externally supplied totals, not recomputation proof. Qualification independently constructs baselines from literal historical tapes. `policy_sha256` hashes policy only (section5); group identity, horizon, eligibility/signing and unit bases must match the target. Actual prior-window producer provenance remains visible.

`FlowCursor` (`flow_cursor`): `stream_id:s, max_position:n`. A snapshot contains all supplied ledger revisions through these cursors, possibly known after a particular requested cut; a cursor is not a completeness claim.

`FlowSnapshot` (`flow_snapshot`): `schema_version:'option-flow-canonical1', bindings:[]FlowBinding, references:[]FlowReference, executions:[]FlowExecution, quotes:[]FlowQuote, groups:[]FlowGroup, populations:[]FlowPopulation, context_certificates:[]FlowContextCertificate, baselines:[]FlowBaseline, cursors:[]FlowCursor`. At most128 streams/groups, <=32 baselines per group. Unique bindings/reference/group/population/certificate/baseline IDs; unique (economic_id,revision_id) within execution/quote families. Exact duplicate facts in typed input are rejected `identity_conflict`; the adapter may deduplicate byte-identical observations explicitly before constructing a snapshot and must expose the count in its conversion receipt. A changed same-identity fact always conflicts. Positions are unique **across both execution and quote revisions in the same stream**, <=its cursor; every referenced stream has exactly one cursor. One stream is scoped to one contract; references with spot order use that same stream. No lexical ID or Python tuple order substitutes for causal source positions.

## 4. Revision selection, causal signing and late facts

Validate the full structural revision graph before cutoff selection: chains are linear, target present, same root/contract/session/stream, position strictly increasing and known_at nondecreasing; no branching/double replacement, cycle or missing retained prefix. New roots identify their market execution/quote order with root position. At cut `(knowledge_cutoff_ns,cursors)`, only revisions known by cutoff and position<=that stream cut cursor are visible. Select the last visible chain revision; cancel removes the output economic fact. Replacements retain root event_ns/root position/signing boundary A for chronology, while their revised economic price/quantity and revision binding participate in hashes. **Temporal profile `option-origin-context1`: output economic revision is selected at K, but signing/reference context is reconstructed at each root's original A from the entire ledger.** A predecessor canceled/replaced after A remains in its state as-of A, even if absent/changed in K-active outputs. Filtering the K-active set to construct historical context is forbidden. A later correction changes later signs only where their own A admits it. Revised target price at K is compared against this original A context; result availability includes the late selected revision known_at, never falsely A. Every target independently reconstructs context. This release claims no constant-time incremental repair, fully restated all-history signing or origin-available revised output.

For a target execution, construct quote revision view **as-of A** (not K). Causal roots have event_ns<=target event_ns, known_at<=A and root position<target root position in its same stream. Choose greatest causal root position **before** checking market-state/age eligibility; the declared stream has nondecreasing root event times. Latest crossed/locked/one-sided/stale/excluded quote yields unknown; do not search backward for a more convenient valid market. A late quote revision absent at A cannot replace the older revision that actually existed at A. Different/incomparable streams have no accepted alignment witness in this profile and yield unknown. `option-quote-midpoint1` has no tick fallback; `option-observed-side1` uses the root's A-admissible supplied classification semantics only; `option-tick1` rebuilds predecessor state as-of this target A partitioned by contract+session+currency+action+definition+stream+policy. Predecessor roots strictly precede target root position, use their revisions at target A, sweep in certified root position order and carry last nonzero tick over equal prices. Compare target's K-selected price to that state. Initial/equal-only history is unknown. Pre-window eligible execution facts seed signing but contribute no window measure; no arbitrary opaque seed or hidden cache. Math document defines exact tie and cluster semantics; quote midpoint equality remains unknown.

Spot eligibility for OTM is independently causal: root historical reference spot event_ns<=execution event_ns, spot_known_at<=A, same stream position<root execution position, age<=max_spot_age_ns; civil reference civil_known_at<=A; definition reference known_at<=A and effective at root event. Missing spot does not disable DTE or premiums; missing civil does not disable OTM or premiums. Negative calendar DTE invalidates only the civil/DTE reference (missing_dte_reference, partial_dte_coverage, not counted in dte_eligible_count); it does not remove a regular execution from base coverage/totals/signing or independently qualified OTM, and creates no FlowExcluded entry. Effective-interval incompatibility remains structural identity_mismatch. No expiry instant is guessed from an ordinal. No observed-side or quote/tick proxy is described as customer intent/dealer positioning. Unknown signs remain explicit bucket/count/premium and coverage witnesses; never silently treated as sell or signed zero without unknown evidence.

## 5. Request and exact result

`FlowPolicy` (`flow_policy`): `schema_version:'r26-flow-policy1', temporal_profile:'option-origin-context1', signing_profile:option-quote-midpoint1|option-tick1|option-observed-side1, max_quote_age_ns:n, max_spot_age_ns:n, short_dte_max_days:n, cluster_max_adjacent_gap_ns:n, horizon_id:s, minimum_matched_prior_windows:n`. short_dte_max_days<=3652058; minimum matched1..32. Policy is global within one request; groups with different policies require separate requests. Premium is price per payoff unit × contracts × multiplier. Quote units and supplied definition units must match this convention. Condition eligibility is exactly regular; source-specific mapping into regular/excluded is adapter-owned and source revision bound. No user-supplied dynamic eligibility rule.

`FlowBaselineTarget` (`flow_baseline_target`): `group_id:s, slot_ids:[]s`. Slot IDs are ordered prior-session target slots, unique,1..32. Missing any expected slot yields missing/incomplete baseline rather than silently dropping it; admitted baseline session_ordinal must be strictly before request.target_session_ordinal, window_end_ns<=request.window_start_ns, known_at_ns<=cutoff and compatible policy/group/horizon. Baseline ordinals strictly increase with target slot order. Selected slot count must meet minimum_matched_prior_windows.

Baseline wrong group/horizon/policy/currency/action, window width unequal to target, overlapping matched windows, nonprior/current/future session or duplicate selected slot is `identity_mismatch` at semantic admission, not unavailable zero. Missing/empty target list is `unavailable/missing_baseline`; declared absent slot `unavailable/incomplete_baseline`; present matching slot with known_at>K `unavailable/future_reference`; incomplete certificate or null selected metric `unavailable/incomplete_baseline`; all slots admitted but count below explicit minimum `unavailable/insufficient_history`. A baseline's other null metric is irrelevant. There can be only one baseline per (group_id,slot_id) in a snapshot; historical revisions need a separate snapshot/cut, not overlapping ambiguous values in this schema. To restore a changed prior baseline use a new slot_id and new target list; retained old baseline is not selected and never mutated. A baseline's population/member hashes may reference external admitted source facts not in current ledger, because they are explicitly supplied historical summaries; they must be well-formed bound assertions rather than claimed locally reconstructed history.

`FlowRequest` (`flow_request`): `schema_version:'option-flow-request1', group_ids:[]s, output_ids:[]s, window_start_ns:n, window_end_ns:n, knowledge_cutoff_ns:n, target_session_ordinal:n, policy:FlowPolicy, baseline_targets:[]FlowBaselineTarget, cut_cursors:[]FlowCursor, formula_version:'option-flow-formulas1', limits:FlowLimits`. start<end<=cutoff (historical completed-window profile); session ordinal1..3652059. Groups/outputs sorted unique nonempty; output IDs exactly the selected entries in FEATURE_BINDINGS.json. Cut cursors contain every snapshot stream exactly once and do not exceed snapshot cursors. Groups must exist. Baseline targets are unique by group; absent targets matter only for baseline outputs. For all other outputs baseline payloads do not become false prerequisites. Full source snapshot remains hash-bound even when only some facts contribute.

Before any evaluation or historical context selection, each selected **active** economic root (a K/cursor-visible active payload in a requested group and window) must have its immutable original signing_boundary_ns A<=request.knowledge_cutoff_ns K. If any violates this, raise `FlowValidationError('identity_mismatch','/request/knowledge_cutoff_ns')` for the whole request; inspect roots in canonical execution_id order and publish nothing. Do not clamp A to K or read context beyond K. This guard is request-specific: a full snapshot may carry future/unselected roots for genuine replay. Example root event10,new known_at10,A30 with window[0,15),K20 fails at that exact pointer; K30 is valid if all other admission conditions pass. A cancelled/nonselected root does not independently trigger this guard, but no context computation may use a fact beyond the applicable target's admitted A<=K.

`FlowCoverage` (`flow_coverage`): `population_id:?s, population_complete:b, expected_count:?n, observed_count:n, eligible_count:n, signed_count:n, unknown_sign_count:n, dte_eligible_count:n, otm_eligible_count:n`. Resolve each economic root at K and cut cursors first. observed_count counts its active regular revision in selected group/window; eligible_count equals observed_count in this scalar profile. Cancelled, excluded, outside-window and roots with no K-visible revision are not in these counts; retain them separately in evidence.exclusions. With a present K-admissible complete certificate, expected_count is count of its declared roots surviving the same K-active regular/group/window selection, and exact membership equality with observed roots is mandatory. Without a complete K-admissible certificate expected_count=null and population_complete=false. Thus cert{a,b} with a cancelled and b regular gives expected=observed=eligible=1; both cancelled gives0/0, not2/0. signed+unknown=eligible; DTE/OTM counts are individually reference-eligible members of that same set. Completeness certifies population, not signing/reference coverage. Output-specific premium-weighted reference ratios are separately exact operands; never interpret these count fields as premium coverage.

**No future-member erasure:** if any expected_execution_id in the selected window has no revision visible at K/cut cursor, its eligibility is unknown, not a cancelled/zero observation. Effective population_complete=false and expected_count=null; all complete-population metrics are unavailable/incomplete_population, although observed_count/base partial operands still show admitted roots. Certificate.complete=true cannot override this. Same applies to expected context roots with no A-visible revision: the target sign is unknown with incomplete_context diagnostic, never a falsely complete seed. Known visible cancellations/excluded roots may legitimately remove eligible count, as the example above distinguishes. `available_at_ns` describes admitted economic value/status causality; it does **not** claim that the full retrospective snapshot/result packet (which explicitly hashes future ledger facts) existed then. Full packet knowledge is K plus its bound supplied-ledger provenance, separate from historical context A.

`FlowCluster` (`flow_cluster`): `cluster_id:h, profile:'option-quote-cluster1', contract_id:s, session_id:s, quote_id:s, quote_revision_id:s, sign:buy|sell, execution_ids:[]s, execution_revision_ids:[]s, first_event_ns:n, last_event_ns:n, venue_ids:[]s, unknown_venue_count:n`. ## 6. Canonical bytes, wire and hash domains

`flow_canonical_bytes(value)` emits UTF-8 JSON, ensure_ascii=False, sort_keys=True, separators=(',',':'), no BOM/whitespace/newline. Cluster paired member arrays retain source-position order; evidence paired active arrays retain execution-ID order; baseline slot/hash pairs retain target-slot order. Ledger causality is positions, never serialized array order. Nested checkpoint history uses same rules. Duplicate keys/result identities are validated before canonicalization, never hidden by set conversion.

Codec type names are precisely each record name given above plus `flow_policy`, `flow_limits`, `flow_rational`, `flow_baseline_target`, `flow_coverage`, `flow_sign_witness`, `flow_request`, `flow_result`, `flow_results`, `flow_checkpoint`, `flow_publication`. No class-name loading or registration. `flow_results` payload is array of results. Envelopes have exactly `schema_version:'option-flow-json1', record_type:s, content_sha256:h, payload:<closed typed payload>`. Decoder parses bounded UTF-8 JSON with duplicate-key rejection, max nesting32 and no NaN/Infinity/exponent Decimal text/float tokens; verifies exact type/version, canonical form and digest. It accepts only byte-for-byte canonical envelopes; noncanonical equivalent JSON fails. Constructor API accepts Decimal objects and exact ints; wire API accepts only canonical strings for Decimal/q components, no implicit coercion.

Exact closed codec functions are `encode_flow_snapshot(snapshot)->bytes`, `decode_flow_snapshot(data:bytes,limits:FlowLimits=FLOW_LIMITS)->FlowSnapshot`; corresponding encode/decode pairs named `flow_request`, `flow_results`, `flow_checkpoint`, `flow_publication`; `encode_flow_record(record_type,value)` / `decode_flow_record(record_type,data,limits=FLOW_LIMITS)` for the other explicitly registered type names. `FLOW_LIMITS` is the immutable default with values in section2.
