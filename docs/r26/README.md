# R26 option flow contracts

R26 adds option-native flow, activity and execution calculations in the existing three option repositories. Canonical scope remains [E34 #533](https://github.com/atulsrivas1/equity-features/issues/533), with all seven delivery stories retained. The owner approved independent native admission under [GOV038 #592](https://github.com/atulsrivas1/equity-features/issues/592); actual EQ153/EQ158 producers still gate EQ190 integration and full R26 acceptance. Local validation and independent review govern merges; hosted CI is optional.

The normative packet consists of [mathematics](MATHEMATICS.md), [feature bindings](FEATURE_BINDINGS.json), [typed boundaries](FLOW_CONTRACT.md), [compatibility](COMPATIBILITY.json), [independent scenarios](INDEPENDENT_FIXTURE_CASES.json) and [fixture construction protocol](FIXTURE_PROTOCOL.md). Freeze authority is the coordinator's externally recorded exact reviewed commit, not mutable status text inside its own commit. Forty-four scenarios are definitions; materialized independent fixtures, executed tests and qualified artifacts remain separate evidence.

The packaging decision adds four optional `option-flow-*` distributions at `0.1.0a1`, in new package directories within the existing repositories. It supersedes the earlier proposal to widen the four R25 distributions to `0.2.0a1`. R25 results embed their original package versions; changing installed metadata while preserving old result bytes would misreport provenance. Keeping flow separate preserves every R25 package source, manifest, entry point and published artifact. The pure flow calculation closure uses its new contracts and the standard library; the complete new runtime contains the four flow distributions plus DuckDB. Original R25 regression uses its original six-distribution cohort. See the compatibility packet for exact dependencies and separate schema/formula/artifact identities.

Implementation proceeds through fresh library, I/O and worker tracks after exact contract freeze. A real contracts-only bootstrap precedes consumer runtime conformance. The coordinator grants bounded, serialized runtime leases after checking active shared-host ownership; source authoring is not an inherited resource grant. Direct, worker, persisted and replay results require complete canonical parity, independent numerical fixtures, both-platform artifact qualification and an actual stored-results browser demonstration. These are future acceptance gates, not claims made by this source packet. No package publication is authorized here.
