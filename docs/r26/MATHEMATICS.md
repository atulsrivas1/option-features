## 1. Exact values, units and admission

An execution has exact decimal price p >= 0 in currency per payoff unit, positive integer quantity q in contracts, and positive exact decimal multiplier m in payoff units per contract. There is no implicit multiplier 100. Its exact premium is P=p*q*m; share-equivalent quantity U=q*m is an explicitly labelled comparison convention, not shares traded, delta exposure or deliverable valuation. Price zero is admitted and gives zero premium; negative price/quantity and nonpositive multiplier are structural errors. Nonstandard deliverables requiring more than the admitted scalar multiplier are unsupported, never guessed as 100.

Decimal arithmetic means coefficient times an integer power of ten, interpreted as an exact rational. It must not depend on binary float conversion, process decimal context, locale, rounding mode or input presentation. Canonical decimal strings have no plus sign, exponent, leading zeros, trailing fractional zeros or negative zero; zero is `0`. Boundary precision bounds apply before arithmetic. Exact integers use canonical decimal strings; all native scalar result values, including counts, use a reduced exact rational `{"numerator":"N","denominator":"D"}` with D>0, gcd(|N|,D)=1 and zero represented 0/1. The unit and value representation are separate fields. No approximate decimal rendering is normative. A UI may display a labelled rounded convenience value while retaining the exact pair.

Apply the boundary's 256-decimal-digit bound to the absolute numerator and positive denominator of every reduced rational intermediate/result, and to exact integer count/accumulator intermediates. Check cancellation by gcd before multiplying rational operands. Exceeding this cap raises the boundary resource-limit exception for the whole request before publication; no saturation, partial row set, infinity, approximation or per-feature numeric-error substitution. The operation order specified below is deterministic. Arithmetic exactness is not provider-data correctness or rigorous proof of economic completeness.

Each result is confined to one currency, underlying/action/deliverable basis, population, group, window, cutoff, formula and profile identity. An underlying group may include mixed admitted multipliers and calls/puts, but cannot combine currencies or incompatible action bases. Mixed incompatible facts require separate declared groups; no FX or corporate-action normalization is performed. Ratios are dimensionless only where numerator and denominator units agree. `premium` uses the group's declared currency, not a hardcoded USD label.

Structural admission precedes calculation in the exact stages of [FLOW_CONTRACT](FLOW_CONTRACT.md): byte/UTF-8/token depth; envelope fields/version/digest shape; duplicate JSON keys/noncanonical scalar/closed record shapes and types; local scalar/cardinality bounds; collection identity/references; revision and causal graphs; request/group/population/baseline compatibility; mathematical evaluation/output coherence. For early shape errors follow field declaration and array index order; thereafter use record declaration order then lexicographic identity, never hash iteration. The boundary supplies exact closed error codes/JSON-pointer paths and duplicate-key-before-digest precedence. Thus malformed facts never become economic `unavailable` results. Unknown economic facts with a valid declared schema remain typed missingness. No result, checkpoint or generation may escape a failed whole-request admission.

## 2. Time, active revisions and populations

All event, knowledge and signing instants are nonnegative integer nanoseconds within the boundary's signed-64-bit range. Windows are [start,end), start<end<=K under this historical completed-window request profile. Membership uses the root execution's event instant: start is included and end excluded. Cutoff K is a separate supplied knowledge instant. The sole supported temporal profile is `option-origin-context1`: select active output economic facts/revisions as-of K, but rebuild each root's historical signing/reference context as-of its immutable original signing boundary A<=K. This is explicitly **revised economic facts against original context**, not an output claimed available at original A and not fully restated all-history signing. Request/result/policy hashes must bind this temporal profile. Evaluation uses no fact/revision beyond its applicable K or A; the request binds the full source prefix and completeness certificate. No wall-clock read occurs in calculation. Every execution root, including a retained context seed, requires its original multiplier/right/strike definition known by its own A. Future original definition is a structural identity_mismatch at its reference_id pointer, not a premium computed from future facts. Unreferenced future definitions remain admissible supplied ledger content.

A root execution plus an immutable linear `new`/`replace`/`cancel` chain represents one economic execution. At a cutoff, its last known applicable revision supplies its active payload, or cancellation removes it. Replacements retain the root economic ID, original event instant, original signing boundary, contract, session, stream partition and original source position; they may change economic price, quantity and admitted classification/reference revision. Corrections to those immutable root fields require explicit cancellation plus a distinct new execution, never an ambiguous relocation. Unknown targets, forks, cycles, cross-root/partition targets, replacement-after-cancel and same-ID different-content conflicts are rejected. A typed snapshot contains each record ID once: even identical duplicated tuple entries are rejected. An adapter or checkpoint-prefix/suffix union may deduplicate identical ID/content records only with an explicit idempotency receipt before constructing that unique snapshot; changed content still conflicts. A complete supplied prefix must contain the target, not a digest alone.

Revision knowledge/order must strictly progress along each chain according to the declared ordered knowledge witness, even when nanosecond knowledge instants tie. Tuple order and lexical IDs cannot create causality. Cutoff generations are immutable: a later cancellation/replacement yields a distinct generation without rewriting an earlier stored result.

Evaluation rebuilds the active output ledger at K and recomputes each affected ordered signing/cluster suffix under the selected temporal profile. For each root, its context prefix at A is reconstructed from the **entire retained immutable ledger**, including predecessors cancelled/replaced later at K. Filtering the K-active output set to event<=target is forbidden: it would leak a future cancellation into earlier signing context. A later correction changes later execution signs only where their A admits that correction; current output price/quantity may nevertheless change at K, and maximal output availability must include every selected revision's known-at. Subtracting a cancelled premium alone is invalid because following admissible tick carries and clusters can change. Batch reduces the whole admitted active view. Chronological cut replay evaluates the complete supplied ledger prefix at each increasing declared cut. A bounded full-prefix-ledger checkpoint retains all admitted fact bytes/revisions, source/order/policy/baseline identities and the previous cut. Restore checks those identities and re-evaluates the bounded full prefix plus new suffix; it is resumability by full-prefix replay, not incremental/live or optimized state reduction. Checkpoint truncation is unsupported. If the full retained prefix exceeds bounds, reject and require a different admitted request rather than discard correction history.

A checkpoint is generated only when request cut cursors equal the complete supplied snapshot cursors. Intermediate replay cuts return null checkpoint, preserving the full supplied ledger for later cuts without pretending a projected partial checkpoint proves future-certificate closure. This does not prevent full-prefix checkpoint restore at an admitted completed cursor.

The eligible population consists of active executions in the window matching its explicit contract/right/expiry/underlying group and declared eligibility policy. Revision visibility requires both known_at<=K and source position<=the request's selected stream cursor. Condition-code eligibility is a caller-bound closed mapping/version, not a guessed provider convention. Definitions effective at event time and known by the admissible observation boundary must agree with the root basis. Visible excluded, cancelled and outside-window roots can legitimately be removed from the eligible count with their witnessed reasons. Each eligible execution belongs once to each selected grouping partition. No top-N filter precedes a full-population denominator.

For complete-population metrics, require a bound complete capture/population witness covering the selected window and eligible membership. A certificate is supplied evidence; the kernel verifies bindings and set arithmetic, not provider truth. Missing/incomplete population makes complete-population values `unavailable/incomplete_population`; observed partial totals may appear only in explicitly labelled evidence, never under the complete metric ID. Complete empty populations have count/quantity/premium 0 with complete=true and event coverage 0/0. Coverage ratios with denominator zero are undefined, not 1. Unknown signs/references do not make the execution population incomplete.

**Expected-member closure is mandatory.** For every expected execution root named by the selected group/window certificate, first determine whether any revision is visible at both K and the selected stream cursor. If no revision is visible, set `population_complete=false` and `expected_count=null`, even when the supplied certificate asserts complete=true. Every complete-population scalar value is then unavailable/incomplete_population; only explicitly partial observed totals may remain in evidence. Do not inspect a future/cursor-hidden price, condition, cancellation, reference or other payload to infer that this root would contribute zero or be excluded. For certificate {a,b}, visible a with premium200 and wholly invisible b cannot produce a complete one-member population or available premium200. A K/cursor-visible cancellation or visible eligibility/window exclusion of b is different and may legitimately remove b from eligible membership. Cursor-only and knowledge-only invisibility must each receive independent conformance cases. A claimed complete empty population is valid only after this closure check; an invisible declared root cannot be turned into an empty-set witness.

Evidence includes the declared population ID/hash, expected eligible count (null under unresolved expected-member closure), observed eligible count, complete flag, active/excluded/cancelled record IDs/hashes, source bindings, exact operands, policy/hash, event-window/cutoff and maximal contributing known-at. The field `available_at_ns` denotes the economic value/status knowledge boundary only; it must include every selected late economic revision and no contributing economic operand can be known after it. It does **not** claim that a retrospective full report packet binding future excluded ledger records/input hashes was available then. Packet provenance may deliberately bind a later supplied full ledger; no actual packet/report publication time is inferred from economic availability. Supplying a future reference cannot retroactively turn an origin result into an available one.

## 3. Three distinct signing profiles

The request selects exactly one of `option-quote-midpoint1`, `option-tick1`, `option-observed-side1`. There is no hybrid/fallback. Every execution carries sign s in {-1,0,+1}, selected method and closed reason. Sign0 is unknown, not inferred selling, not an omitted row and not market intent. Signed sums intentionally contribute zero from s0 while retaining its premium/count and sign coverage.

Signing context has its own completeness/admission witness, distinct from complete execution membership in the output window. Tick context requires a certified retained prefix from declared session start through the target causal boundary; quote alignment requires a bound latest-in-stream selection/capture witness at that boundary. A digest alone cannot prove either. Any context certificate expected root with no A/cursor-visible revision makes context incomplete; do not filter it away using a future cancellation or excluded payload. Without the required complete context witness, sign is unknown (`tick_seed_unavailable` or `quote_missing`) with `incomplete_context` diagnostic; window counts/premium remain available when their separate execution-population certificate is complete. The kernel checks witness binding/set/range consistency, not provider truth. Supplied partial prefixes cannot be presented as exact current last-price state.

**Quote midpoint.** For an execution at event time t with original signing-availability boundary a, only quotes with event<=t, known_at<=a and a<=cutoff are causal candidates. Their effective interval and contract/currency/basis must match. The sole admitted ordering profile uses one shared stream for quote and execution facts; selection is its greatest admissible source-order position, with event times nondecreasing in that stream. After selection require age t-quote_event<=max_quote_age_ns; equality is admitted. Shared-stream ordering must place quote strictly before execution, including an equal-time tie. Independent feed timestamps or lexical-ID order are insufficient. Cross-stream causal witnesses and competing-stream ranking are unsupported/deferred; this contract has no field that can certify them.

Quote revisions are viewed as of the execution's original signing boundary, not the later evaluation cutoff. A later-known correction cannot improve historical quote availability. A correction of execution price may change comparison to that same causal quote view. Future quote records remain excluded. The latest causal quote is selected before checking its economic market state: a locked/crossed latest quote is unknown, never replaced by an older more convenient valid quote. Outdated quotes are stale rather than silently refreshed.

For selected bid b>=0 and ask h>=0 with b<h, compare exact 2p with b+h: greater gives +1, less gives -1, equality gives 0. Inside-spread prices are classified by midpoint under this original profile. Prices outside the spread are still classified by this comparison and explicitly flagged `outside_spread`; they are not clipped. Locked b=h and crossed b>h give sign0. Missing/one-sided quotes, absent causal witnesses and future/stale observations give sign0. There is no epsilon or binary rounding. Quote selection, quote ID/revision, age, source witness, exact midpoint operands and reason are retained.

**Option tick.** Partition by contract + session + currency/action/definition basis + source/sign-policy identity. For a target execution, reconstruct active eligible predecessor roots from the entire ledger as-of its A, strictly before its original source position, and sweep that predecessor context in certified source-position order with nondecreasing event time. Predecessor prices use their admitted revisions at this target A, not their later K revisions. Carry prior price and last nonzero sign only inside that partition. A seed means the actual supplied historical execution prefix, including pre-window roots and their revisions, never an arbitrary last-price/sign scalar. Each seed predecessor must have certified earlier source order and known_at<=target A. Empty prefix means no prior price and no sign. For each context predecessor, price increase/decrease gives +1/-1; equal price carries the previous nonzero sign, or0 if none. The first context observation without prior price is0. After each update prior price; update carried sign only when nonzero. Ineligible/cancelled-as-of-A predecessors do not seed or advance state. Apply that final context state to the target's selected economic price at K using the same comparison/carry rule. Later K-active targets each reconstruct their own A context independently; do not carry a target's revised-K price into another root whose A cannot know it. A predecessor cancelled later at K remains in an earlier A context; a correction known by a later root's A can change that later state. Recomputing full causal prefixes, rather than a single mutable sweep leaking late data, is the reference behavior. Record context prefix hash/A and selected target revision hash/K separately.

This is option-owned arithmetic over option records, not qualification of shared equity tick arithmetic or an accepted EQ158 producer. A generic equity-kernel reuse profile requires separate actual compatibility review and is unsupported here.

**Observed side.** A supplied observed-side fact has value buy/sell/unknown, closed source semantics ID, knowledge/order witness and original binding. Use the original root's supplied side/semantics/knowledge fact only, admitted when known by that root's A. A later classification replacement can revise economic eligibility but cannot replace this original side context. Buy maps+1, sell-1, unknown0. No root side source or inadmissible/future root side gives0. It is a supplied classification, not proof of customer opening/closing intent, dealer inventory or trade aggressor ground truth.

Closed sign reasons: `quote_above_midpoint`, `quote_below_midpoint`, `quote_midpoint`, `quote_locked`, `quote_crossed`, `quote_missing`, `quote_one_sided`, `quote_stale`, `quote_future`, `quote_order_unknown`, `tick_up`, `tick_down`, `tick_carried`, `tick_initial_unknown`, `tick_seed_unavailable`, `observed_buy`, `observed_sell`, `observed_unknown`, `observed_missing`, `observed_future`. Where several unknown causes occur, use missing -> future -> order_unknown -> stale -> one_sided -> locked -> crossed -> midpoint. This precedence chooses a primary reason; retain every discovered cause in sorted diagnostics. Structural basis conflicts never enter this economic precedence. Fully restated all-history signing and hybrid quote/tick restatement are unsupported profiles and remain explicit EQ188 residuals.

## 4. Exact rollups, direction and concentration (EQ189)

For the admitted complete group E, traverse canonical active economic-root order (partition ID, original source position, root ID) for exact accumulations; lexical partition order gives deterministic reduction only and does not create cross-stream causality. Let C=sum q, U=sum q*m, T=sum P, N=|E|. Let A=sum P for s+1, B=sum P for s-1, Z=sum P for s0; A+B+Z=T. Sign-known count is count(s!=0); its event coverage is known_count/N, while known-premium coverage is (A+B)/T. These are distinct measures, including when zero-price executions exist.

Native outputs: `flow.trade_count`=N, `flow.contracts`=C, `flow.share_equivalent`=U, `flow.premium`=T; `flow.buy_proxy_premium`=A, `flow.sell_proxy_premium`=B, `flow.unknown_premium`=Z; `flow.signed_execution_premium`=A-B; `flow.known_sign_imbalance`=(A-B)/(A+B); `flow.total_premium_imbalance`=(A-B)/T; `flow.unknown_premium_share`=Z/T; `flow.sign_event_coverage`=known_count/N; `flow.sign_premium_coverage`=(A+B)/T. A ratio denominator0 gives `undefined/zero_denominator` with exact operands, even for numerator0. Totals and signed totals are available0 for complete empty populations.

Right-adjusted direction d=s for calls and d=-s for puts. Let D+ and D- sum P where d+1/d-1, with D0=Z. `flow.right_positive_premium`=D+, `flow.right_negative_premium`=D-, and the named matrix identity `flow.net_directional_premium`=D+-D-. This explicit convention can be positive for a call buyer or put seller. It is not investor bullish/bearish intent, delta-weighted exposure, multi-leg direction, opening/closing flow or dealer positioning.

`flow.call_premium` and `flow.put_premium` partition T by right; `flow.put_call_premium_ratio`=put/call if call>0, otherwise undefined, including put=0. Calls/puts and signs are not interchangeable partitions.

For a declared complete partition j of the group by contract or expiry, accumulate g_j=sum P of its members, include positive and zero groups in evidence, and verify sum g_j=T. For T>0, `flow.contract_hhi` and `flow.expiry_hhi` are sum(g_j*g_j)/(T*T), multiplying and accumulating in canonical partition-key order; `flow.contract_top_share` and `flow.expiry_top_share` are max(g_j)/T. For T0 all four are undefined/zero_denominator, not concentration1 or0. All tied top IDs are retained in canonical order; no arbitrary winning identity. HHI/top use the entire selected eligible population, not a prefiltered top set. Averaging HHIs, top shares or ratios from chunks is invalid. Exact disjoint totals can be merged only with proof of nonoverlap and identical definitions/policies/population; sign state, clusters and baseline medians need full ordering/population reconstruction.

## 5. Quote-aligned temporal clusters (EQ215)

`option-quote-cluster1` is a disjoint temporal partition over active eligible executions with known nonzero sign from `option-quote-midpoint1` and an admitted selected quote. Other signing profiles cannot produce this cluster profile and yield `unsupported/unsupported_profile` for cluster outputs alone. Partition by contract/session/currency/action/definition/source-sign-policy. Order by certified economic source positions. Start a cluster at the first eligible member. Append the next execution only when its selected quote ID+revision, sign, and partition are identical and event gap from the previous member is <=cluster_max_adjacent_gap_ns. Equality at the gap limit is included. Quote change, sign change, session/basis change or gap>limit closes the cluster. An unknown-sign or unavailable-quote eligible execution breaks the run and is not bridged; cancelled/ineligible records are absent from the eligible sequence. A zero-price signed member is a member with premium0. Cluster identity hashes profile/partition/first-member identity/ordered membership, not the display ordinal.

The named `execution.cluster_premium` emits one result per nonempty cluster: sum P over its members. Additional measures are `execution.cluster_trade_count`, `execution.cluster_contracts`, `execution.cluster_span_ns`=last_event-first_event, `execution.cluster_venue_count`=number of distinct admitted venue IDs (missing venue is unknown and does not invent a venue), and `execution.cluster_coverage`=sum clustered P/T for the enclosing group. Unknown venue count is retained separately in evidence; venue-count value is unavailable/missing_venue_reference when any member lacks an admitted venue. Full group population completeness is required for maximal cluster boundaries; partial data does not justify a complete cluster. Complete empty groups emit no per-cluster rows and one enclosing cluster_coverage result undefined/zero_denominator. A complete nonempty group with no known-sign clusters emits no cluster rows and coverage0 when T>0.

Adjacent-gap transitivity can make total cluster span exceed the gap limit. This is deliberately distinct from maximum-span-from-first clustering, overlapping windows, exact repeated-print grouping or four-decimal formatted-premium grouping. None proves common customer, sweep, parent order, iceberg, participant, multi-leg strategy or intent. Those source variants retain explicit residual ownership in FEATURE_BINDINGS; they are not claimed delivered by this original profile.

## 6. Prior-only baselines (EQ215)

For each target group and metric contracts/trade_count/premium, the request declares a finite ordered list of prior slot identities and `minimum_matched_prior_windows` in1..32. All declared slots are required, with at most32. A slot binds completed prior session ordinal, exact start/end, horizon ID, group/cohort identity, currency/action/deliverable basis, metric units, eligibility profile, population certificate and source revision. Sessions must be strictly prior to the target civil/session ordinal; each prior window must end<=target start and be complete/known by the request cutoff. The same horizon ID includes calendar/session policy, intraday anchor and duration; matching width alone is insufficient. Current/future sessions and duplicate/overlapping slot IDs are structural request errors; missing/incomplete declared observations are typed unavailable. Do not select the last N available observations, use future baseline revisions, or silently use a different contract/cohort after expiry. Supplied baseline summaries are operands with explicit provenance, not proof of an actual equity or option producer.

Admission requires every declared slot present, compatible and complete, and n>=minimum. Zero declared slots gives unavailable/missing_baseline. A missing slot gives unavailable/incomplete_baseline; a matching supplied slot known after K gives unavailable/future_reference; an incomplete certificate or null selected metric gives unavailable/incomplete_baseline; n below minimum gives unavailable/insufficient_history. Contracts, trade_count and premium scalars in a slot are independently nullable: a missing premium metric does not block contracts/trade-count baselines. Wrong horizon, currency, action, policy or group identity is structural identity_mismatch, as are overlapping prior windows and current/future-session slot declarations. No default minimum20 or product score/extreme threshold is inherited. Requests must supply their chosen minimum, which is an output identity operand. Tiny fixtures with minimum1..4 qualify exact arithmetic only under that explicit policy.

Sort exact nonnegative scalar history values x. Median M is the middle value for odd n or the exact average of the two central values for even n. Sort exact |x-M| and take its median MAD with the same rule. Sum/order operations remain exact; ties preserve all member identities in evidence. `activity.contracts_median`, `activity.trade_count_median`, `activity.premium_median` and `activity.premium_mad` expose these corresponding diagnostics. Each metric requires its own compatible baseline; one unavailable metric does not block the others.

The named `activity.relative_volume` is current C divided by contracts median M; `activity.relative_trade_count` is current N divided by trade-count median. If M=0, value is undefined/zero_denominator for both zero and positive current values, retaining M/current/n. No infinity/finite-extreme sentinel or fallback1. Named `activity.premium_robust_z`=(current T-premium M)/(7413/5000 * premium MAD). The scale7413/5000 is an exact declared convention, not a fitted distribution or significance claim. MAD0 gives undefined/zero_mad even when current==M; retain current/M/MAD/n. When current0 and median>0, relative0 is available; robust z may be negative. No percentile, trigger, screen threshold, extreme sentinel or ranking is introduced by this profile.

Historical corrections produce different baseline revision/knowledge hashes and later request generations. At an earlier cutoff retain its earlier supplied baseline version. Restore/replay must not reuse a baseline prepared at a later cutoff for an earlier cut. Medians/MAD cannot be merged by averaging chunk medians/MAD; all declared values are retained for reference evaluation.

## 7. DTE, OTM and independent reference coverage (EQ215)

Each eligible execution has an independently admitted civil/expiry binding and, optionally, spot binding. A civil ordinal is a proleptic-Gregorian integer day under the supplied calendar/timezone revision; the kernel validates matching identities and bound execution instant, not timezone conversion. DTE=expiry_ordinal-execution_civil_ordinal. A negative calendar DTE (expiry_ordinal<civil_ordinal) invalidates only this civil/DTE reference: retain the regular execution in base totals, signs and independently admitted OTM measures, exclude it from dte_eligible_count, and record missing_dte_reference with partial_dte_coverage. Do not add a FlowExcluded entry or infer an expiry instant from a civil ordinal. Full short-DTE share is unavailable/missing_dte_reference; reference coverage and observed lower share retain their qualified-reference operands, while conditional share with no known-reference premium is undefined/zero_denominator. `short_dte_max_days` is a supplied nonnegative integer bounded by the boundary schema. Short means0<=DTE<=max inclusive. DTE0 is a valid civil reference provided the explicit definition effective interval contains the execution event. An effective-interval mismatch is structural identity_mismatch; this profile admits no additional guessed expiry-instant exclusion.

Let R_D=sum P with valid civil/DTE reference, D=sum P within that short range. `flow.dte_reference_coverage`=R_D/T and `flow.short_dte_known_reference_share`=D/R_D when denominators>0. Named `flow.short_dte_premium_share`=D/T only when every eligible execution has an admitted DTE reference; otherwise unavailable/missing_dte_reference even if missing rows have zero premium. `flow.short_dte_observed_lower_share`=D/T may be available with partial reference and is explicitly a lower observed share, never the complete named feature. DTE admission does not require spot.

For OTM use admitted exact strike K>0 and causal spot S>0 in the same underlying/currency/action basis. Spot event<=execution event, known_at<=original signing boundary, age<=max_spot_age_ns, and shared-stream source position must be strictly before execution. Cross-stream alignment is unsupported in this profile. A late-known or stale spot is unknown for that execution. Calls are OTM iff K>S; puts iff K<S. Equality is ATM and not OTM. No percentage tolerance, forward moneyness, delta test, crossed-market guess or later reference fallback. The root's original reference binds historical spot/civil context at A; a later changed economic reference must agree with its immutable definition and cannot introduce late-known context. Civil knowledge is checked independently of definition/spot knowledge. The kernel checks this explicit reference witness rather than fetching a quote.

Let R_O=sum P with valid OTM reference and O=sum P among those OTM. `flow.otm_reference_coverage`=R_O/T; `flow.otm_known_reference_share`=O/R_O; named `flow.otm_premium_share`=O/T only when every eligible execution has an admitted OTM reference, else unavailable/missing_spot_reference. `flow.otm_observed_lower_share`=O/T explicitly permits incomplete reference. Missing spot cannot block DTE-only outputs. Missing civil data cannot block OTM when strike/right/spot basis and effective definitions are valid. Zero total gives undefined/zero_denominator for shares after population/reference admission; complete empty needs no per-execution references and its full shares are undefined, not unavailable. Known conditional shares and coverage retain separate denominators and member identities.

## 8. EQ190 retained equity integration boundary

These are specified consumer semantics, **not admission to implement missing equity mathematics**. Full EQ190 and R26 require actual compatible qualified EQ158 equity signed rollups and EQ153 correlation; EQ159 remains a gate where an accepted shared quote-dynamics profile is selected. Source-level interfaces or synthetic supplied operands cannot satisfy producer delivery/artifact integration. Absent accepted producers the cross-asset profile is `unsupported/equity_integration_unqualified`, with the exact unmet producer IDs. All native outputs above remain independently specifiable.

Participation pairs compatible complete same-underlying/currency/action/window/cutoff populations. Equity producer returns exact nonnegative equity shares V and dollar turnover W with its actual producer/formula/artifact/source/population hashes. `cross.share_equivalent_participation`=U/V and `cross.premium_turnover_participation`=T/W, each denominator>0; zero gives undefined/zero_denominator. Ratios may exceed1; neither is a bounded fraction of one common traded population. Missing/incompatible/future equity gives typed unavailable, never zero. Equity-side rollup and side inference are not computed by the option library. Pure exact division of admitted operands does not prove end-to-end equity integration.

For descriptive lag, option-side complete signed premium buckets x_t=sum s*P use the admitted option sign policy and preserve unknown premium/count; equity y_t is the actual admitted equity signed-dollar producer. Bucket grid has exact integer anchor,width, contiguous session-bound windows and no partially included bucket. Missing bucket is missing, not zero; complete empty bucket can be0 only with a capture witness. For integer lag k, pair x_t with y_(t+k). Positive k compares option with later equity. All paired data must be known by cutoff; result availability is no earlier than maximum paired-bucket availability. This is retrospective descriptive association, not causal leadership or origin-time predictive information.

The accepted correlation producer receives canonical ordered exact aligned pairs, requires n>=3 (a request may require a larger explicit minimum), and positive centered sums of squares. Its mathematical target is Pearson r=sum((x-xbar)*(y-ybar))/sqrt(sum((x-xbar)^2)*sum((y-ybar)^2)). EQ153 owns the arithmetic, rendering/error contract, exact artifact and numerical qualification; R26 must not choose a float tolerance or invent that producer's result schema here. `cross.lag_correlation` is therefore a reserved output until that concrete accepted compatibility contract is frozen. Pair count, exact member list/hash, lag convention, grid, omissions and variance status are required consumer evidence. Zero variance gives undefined/zero_variance; too few complete pairs gives undefined/insufficient_pairs. Do not output an all-unsupported placeholder and call EQ190 delivered. Beta/residual/leadership scores are outside this selected consumer scope.

## 9. Results, reason priority and evidence

There are exactly44 native output IDs: six named matrix identities plus38 additional typed measures. FEATURE_BINDINGS enumerates them and the closed unit assignment. Three cross-asset IDs are reserved separately and do not count as native implementation. A request selects a nonempty set of output IDs and groups. Each selected group/scalar feature produces exactly one row; the five per-cluster features (premium, trade_count, contracts, span_ns, venue_count) produce one row per maximal nonempty cluster, which may be zero rows.
