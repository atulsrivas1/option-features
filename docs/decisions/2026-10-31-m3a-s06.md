# 2026-10-31: M3a S06 chain point outputs V5, V6, V8, V11, V21, Developer choices

mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12

Status: Developer choice (S06), for code and architecture review. Scope: `option_features/surface_points.py` (M3A-4, M3A-5, M3A-7, M3A-10, M3A-11), `tests/m3a/test_surface_points.py`, and one additive S05 key (item 2). R-31 to R-38, R-84, R-116, R-131, R-133, R-137, R-139, R-162, R-178 to R-185 and the IO contract sections 3 and 8 settle the rules; the items below are what they leave open.

1. Interface. `point_from_frame(output_id, frame, floats, params, labels)` is the O(1) step the runner calls once per output on a frame it already built (`frame` the M3A-0 Result, `floats` = `stats["floats"]`, `labels` = `stats["labels"]`); `point_output(output_id, contracts, spot, rate, dividend_yield, cutoff_ns, params, chain=None, contract_ivs=None)` validates (S09 `validate_request`, structural codes first, R-131), builds the frame with the tenors the output needs (V5 [9, 30, 91], V11 and V21 [30], V6 and V8 none) and derives. One frame can feed all five outputs. The request `tenors` and `delta_convention` are not forwarded where the output does not read them (V5 and V6 ignore the convention, R-174).
2. One additive S05 key, `stats["labels"]` (this IS the S05d labels shape, ruled by the architecture review; S05d no longer needs a separate labels PR; S07 reads the same shape). R-180 says labels are output-level (only expiries the output uses) and R-105 gives an unavailable frame `labels` []. Most V5 and V6 rows are available outputs on frames that are unavailable as a whole (no 25-delta bracket, R-141), so the frame's own labels are [] and cannot be used. `surface_frame` therefore also fills a TOP-LEVEL `stats["labels"]` (beside `stats["floats"]`, never inside it, so `floats` stays byte-identical): {str(days): {"label": model label of the ATM legs, None unless the expiry is available; "put25_labels", "call25_labels": sorted distinct labels of the bracket strikes actually used, [] when that side is unavailable; "covered": False only when the expiry's reason is low_surface_coverage, True otherwise}}, one entry per listed expiry whether available or not, absent on an early or invalid return, cleared on entry like `floats`. Frame text, floats, coverage, labels and hashes are untouched. The S05c golden digest in `tests/m3a/test_surfaceframe_available.py` hashed `sorted(stats)`; it now ignores the `labels` key (one-line edit), every other part is unchanged and still equals the digests taken on main. `LabelsShape` pins the shape on every S05-owned row (covered False, unavailable expiry, approximate label, empty side, early return). S06 tolerates a missing key or entry (treated as no label).
3. Availability comes from the frame ITEMS, not the frame status. The frame is unavailable as soon as any listed expiry, requested tenor or side fails (R-141), but "each pair independent" (matrix) and the rows (V5, V6) want the output available when its own inputs are. So: V5 reads the two tenors of the requested pair (shorter first); V6 reads the per-expiry statuses; V8 reads the per-expiry 25-delta sides; V11 and V21 read the 30-day tenor and the sides. The only frame-level rule applied first is R-106 / R-162: no eligible strike in the whole chain (`coverage.eligible_strikes` 0, which covers an empty chain and a chain where every contract fails the gates) is `no_eligible_contract`, which wins over every output-level count (V6-NE rows).
4. V5 (PO to rule). `value.pairs` shows every pair that is available ({"9_30", "30_91": {longer, shorter, spread_points}}, longer minus shorter, R-31); the request `pair` ("9-30" default; the rows always give it) selects the pair that decides availability and the fire decision. A requested pair that fails gives the failing tenor's reason (the shorter tenor first). The default pair is my choice (the contract lists `pair` without a default).
5. V6. Eligible expiries are the frame items with status available (an expiry without an ATM strike, failing coverage or with a solver failure is skipped, R-32); fewer than two is `fewer_than_two_expiries`. `spread_points` = second minus nearest.
6. V8, V11, V21 (R-28). Each 25-delta side is taken to the 30-day tenor separately: the S04 tenor kernel runs over the per-expiry side values (an expiry whose side is missing carries that side's reason, an expiry that is unavailable carries its own), so exact-expiry, bracketing, `no_bracketing_expiry` for a coverage-excluded bracketing expiry (R-139) and `low_surface_coverage` for an exact expiry that fails coverage (R-178) are the kernel's rules, unchanged. `no_delta_bracket` passes through from a bracketing expiry that lacks a side. Failure precedence: V8 put then call; V11 and V21 the ATM tenor, then the put side, then the call side (R-137); V21's `zero_denominator` after those.
7. Rounding (R-48, R-181; "all threshold and sign decisions use the rounded decimals"). Every point value is the EXACT difference of the unrounded binary64 values times 100, rounded once half to even (integer arithmetic on `as_integer_ratio`, as S10). V11: `wings_mid` = exact (put + call) / 2 rounded once; `curvature_points` = exact (wings_mid - ATM) x 100 rounded once. V21: `put_distance` and `call_distance` are rounded once; `ratio` is the exact ratio of the two UNROUNDED distances rounded once (not the ratio of the rounded distances: row V21-D4 pins that); a call distance that rounds to 0 is `zero_denominator` (R-38, rows V21-E). The fire decision compares the rounded decimal with the threshold, inclusive (R-35).
8. Fire rules and thresholds (PO to rule: `either` on V21 and the wrong-key rule). `direction` in {up (default), down, either}; the threshold key follows the direction (up `at_least`, down `at_most`, either `x`; the rows never mix them); a missing key takes the default of R-36 (3 points for V5, V6, V11, 5 for V8), V21 has none (`threshold_required` from S09). Points forms: up fires at value >= thr, down at value <= -thr (R-133), either at |value| >= thr. V21 compares the ratio itself: up at ratio >= thr, down at ratio <= thr (R-133), negative thresholds allowed (rows V21-D3, D4). `either` on V21 is meaningless for a ratio (D-06) and no row uses it: I read it as |ratio| >= thr. A threshold under the wrong key (down with `at_least`) is ignored and the default applies. Defensive codes inside `point_from_frame` (a caller that skipped S09): `invalid_direction`, `threshold_required`, and `malformed_type` for a threshold that is not a number or decimal text.
9. Echo. `params` carries the S05 echo plus `direction`, the threshold under its key (default filled), `pair` (V5) and `delta_convention` (V8, V11, V21 only); `value` never carries `delta_convention` (R-184). The author3 V8, V11 and V21 rows list `delta_convention` in `expected.assert`; the test reads it from `params` (and asserts it is absent from `value`), as R-184 requires. Labels: the labels of the expiries and bracket strikes the output uses (V5 the tenors' expiries of every pair shown, so the expiries of the non-requested pair are labelled when that pair is also shown (R-180: they are shown values), V6 the two expiries, V8 the bracket strikes of both sides at the expiries the 30-day value uses, V11 and V21 those plus the ATM tenor's expiries), plus "delayed" under a delayed tag; [] when not available.
10. Rows. 218 rows (V5 40, V6 34, V8 66, V11 38, V21 40, structural-tagged rows included) pass. The 15 boundary-exact rows (`gating` false, R-182, `expected.boundary.exact`) assert the fire decision as well; the other 5 near-threshold rows (3 V5, 2 V6) assert every value but the fire decision (non-gating as tagged, R-140). Structural rows (convention, malformed, `threshold_required`) go through S09 unchanged.
11. Tests and evidence (Developer evidence, synthetic workload). (a) A pure-Python reference in the test file, written from the rulings with `Fraction`s and its own tenor bracketing, against random synthetic frames (no chain, no solver; every failure precedence is reached): `Differential` runs 24,000 cases in the suite and 200,000 cases (5 seeds x 40,000) outside it, 0 differences in statuses, reasons, value texts, fire decisions and labels. (b) Mutation check: 59 single-edit mutants of `surface_points.py` (fire operators and signs, direction keys, defaults, rounding ties and scale, expiry order and filters, sides swap, precedence order, zero check, sign normalisation, labels, echo, validation, exception guard), all 59 killed. (c) The first draft of the module was caught by the new tests on two defects: a ratio of two values with a negative denominator rounded the wrong way (the integer rounding helper needs a positive denominator), and `point_output` raised a KeyError for an output id it does not serve; a third finding changed the ratio basis (item 7). (d) Unit tests: round-once, ties, inclusive boundaries, every direction, defaults, precedence, labels, hostile frames and requests, trusted-chain path equals the validating path.
12. Performance (W05, M3A-B4: <= 1 ms per name, <= 110 ms per 103 names, hard 5 ms and 550 ms; synthetic workload, relative engineering budget). The unit test is a smoke check (`m3a_harness.best_of`, floors unchanged). Developer measurement, all five outputs per name from cached frames (8 expiries bracketing 9, 30 and 91 days), 1 warm-up and 30 repeats in a fresh process, three processes: per name p50 0.173 ms (p95 0.195 to 0.218 ms), batch of 103 p50 18.0 to 18.6 ms (p95 18.9 to 20.0 ms). The G0 share: the M3A-0 frame increment is about 13 ms (W02, S05c), so the five point outputs add about 1.3 percent on top of one frame. The Tester's bench is the gate.
