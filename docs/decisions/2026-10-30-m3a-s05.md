# 2026-10-30: M3a S05 surface frame, Developer choices

mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12

Status: Developer choice (S05), for code and architecture review. The rulings R-103 to R-109, R-139, R-141, R-142 and R-178 settle the rules. They leave the following open.

1. ATM on eligible legs (R-109). The frame's ATM strike is the chainiv rule (nearest the forward, ties to the lower strike, chainiv's exact `_Forward` compare). It is applied only to strikes whose call AND put are both available after gates, style and solve. A solver failure on an ATM leg therefore moves the ATM strike. This is what SUR-45, SUR-85, SUR-88 and SUR-93 expect ("ATM moves"). M1 `IVChain.atm_iv` does not fall back, so S05 does not call it. The M1 behaviour and bytes are unchanged.
2. `no_eligible_contract` placement (R-106 against R-141). The frame reason is the first failing expiry. If no expiry fails and no contract is eligible (only possible for an empty chain), the reason is `no_eligible_contract`. After that come the tenors, then the 25-delta sides. This is what the rows give: SUR-61 (all stale) gives `no_atm_strike`, and SUR-66 (empty chain) gives `no_eligible_contract`.
3. Style values. A style that is not "european" or "american", None included, is the contract reason `style_unknown` and is not `malformed_type`. This is what SUR-60, SUR-64 and AME-13..16 expect, and it is the M1 behaviour. Settled by Architect ruling R-187 (the contract text yields, to be clarified in a later docs PR, no fixture change): a style that is neither None nor a string (for example 5) is `malformed_type` at position 10, checked on the untrusted path before any IV work. `condition` keeps the type check.
4. Unavailable expiry items. `forward` is always shown (chainiv forward, 8-decimal text). `atm_iv` is null. `put25_iv` and `call25_iv` are {unavailable, the expiry reason, null}. The rows assert only status and reason for these items.
5. Labels on an available frame. The sorted model labels of the contracts used are the ATM legs of every expiry and the two bracket strikes of every 25-delta side, plus "delayed" under a delayed tag. An unavailable frame gets [] (R-105).
6. Hostile inputs (S03 review follow-up). On the untrusted path (no `chain` given; a trusted caller passes the IVChain it built), the fields the frame reads are validated in the request-list order before anything else runs. `bad_spot` covers 0, negative and non-finite spot. `bad_strike` covers strike <= 0. `bad_rate` covers a non-finite or out-of-range rate or yield. Type and representation errors are `malformed_type`. Any residual exception is mapped to `malformed_type`, so `surface_frame` never raises on caller data. A cached contract IV that is not a finite float >= 0 excludes that contract and is not counted, because no closed reason fits and IVChain never returns one. No NaN or inf reaches the S03 kernel. The full structural precedence (`tenor_not_allowed`, thresholds and the rest) is S09's. `tenor_not_allowed` is not applied here, because author1 rows request listed expiries as tenors (for example [14], [120]).
7. Cache interface. `surface_frame(..., chain=None, contract_ivs=None, stats=None)`. When `contract_ivs` (the `IVChain.contract_iv()` map) is supplied, the frame does no IV work and builds no chain. This is the M3A-B1 "contract IVs cached" path. `stats["evaluations"]` returns the M3A-B12 counter. `expiry_records` exposes the coverage-gated tenor inputs, which `tests/m3a/adapt_tenors.py` now uses.
