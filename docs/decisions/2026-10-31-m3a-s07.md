# 2026-10-31: M3a S07 change outputs V4, V7, V10, Developer choices
mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12
Status: Developer choice (S07), for code and architecture review. Author: Developer. No spec text, fixture or manifest is edited.

## What S07 delivers
`option_features/surface_change.py`: `iv_change` (M3A-3, V4, both `iv_form`), `gap_change` (M3A-6, V7, n-th prior session),
`skew_change` (M3A-9, V10, `change` and `sign_change`). `tests/m3a/test_surface_change.py` owns the 188 rows of author3
`m3a_cases_v4.json` (80, incl. V4-S-01..09 and V4-Cx1), `v7` (44), `v10` (64) and uses `m3a_g5_priors.json`;
`tests/m3a/adapt_surface_change.py` is its adapter. Interfaces and value shapes are in the module docstring.

## Choices (ambiguities of the spec, each with the choice made)
1. Inputs. The functions take the S05 frame `Result` and its `stats["floats"]` (R-189), not a chain: S05 owns IV solving,
   coverage and the 25-delta kernel. Only the items an output reads decide its status (a failed 25-delta side of another
   expiry does not make V4 or V7 unavailable; R-141 is about the frame status, which V4 and V7 do not use).
2. Structural codes. The S09 validator runs on the PARAMETERS (`validate_request(oid, (), ...)` with no contracts, so
   chain positions 6 to 9 and 11 stay the frame's) and is merged with the frame's own `invalid_input` code by (position,
   slot): the lower wins, the frame's on a tie. V4 to V7 take no `delta_convention` (R-149): the caller builds their frame
   without it (a bad value there is the frame's code); the S07 functions never read it for V4 and V7.
3. Prior readings (R-40). `params["prior"]` = {kind "frame" | "session", value, time_ns}; value is decimal text, int,
   Fraction or finite float, rounded half-even to 10^-8 BEFORE use (so sign and change are on the rounded value). A
   bool, unparsable text, other type or an unknown kind is `malformed_type`. `params["priors"]` is a list of readings
   (time_ns, optional delta_convention and session_id) that only feeds the position-17 checks of ALL supplied readings
   (R-134): the store itself has no reading times. V4 takes its prior only as an input; a session prior of V4 is the
   caller's read of `atm_iv_close` / `iv30_close`.
4. History (R-136, R-192, R-195). V7 and V10 session kind read `m3a_history.scalar_baseline(min_sessions=max_sessions=n)`
   of the lane of the request; the read STATUS is checked before any value is used. invalid_input -> its code (view-read
   structural codes, incl. `convention_mismatch` for a skew series of the other convention); unavailable with n 0 (empty
   store, no store, another lane) -> `no_prior_reading`; unavailable with 0 < n < requested -> `insufficient_history`.
   A scalar stored 0 is a real value (R-195 concerns minute series only; this story reads scalars only). n-th prior =
   the oldest of the n values; `priors` lists the n sessions, most recent first (D-15).
5. Order. structural, then history-read codes, then upstream reasons (`no_eligible_contract` first, then the output's
   items), then `no_prior_reading` / `insufficient_history`, then `zero_denominator`, then the threshold (IO contract
   section 8 item 7).
6. `no_eligible_contract` (R-106) is decided from the frame coverage (`eligible_strikes == 0`), before every other
   upstream reason: the S05 frame reason for "every contract is stale or late" is `no_atm_strike` (first failing
   expiry), while the rows V4-NE2/NE3, V7-NE2/NE3, V10-NE2/NE3 expect `no_eligible_contract`.
7. V4 ATM form (R-151). Nearest ELIGIBLE expiry = lowest days whose frame status is available; an expiry with reason
   `low_surface_coverage` is skipped; any other failure of the nearest covered expiry (`no_atm_strike`, a solver
   reason) is the result reason with no fall-back (row V4-A-17). If every expiry is `low_surface_coverage` the reason is
   `low_surface_coverage`. Ambiguity: an expiry that has no strike eligible for both rights AND also fails coverage is
   reported by S05 as `no_atm_strike` (R-103 order), so it is not skipped; the frame does not say which.
8. V4 arithmetic and rule. now = round-once of the selected float; prior as item 3; change = now - prior in integer
   10^-8 units; change_points = change x 100 (exact); change_ratio = change / prior half-even to 8 decimals;
   `zero_denominator` for prior 0. The rule is applied to the ROUNDED change_ratio decimal in percent (IO contract
   "threshold decisions use the rounded decimals"): up >= T, down <= -T (R-133), either |.| >= T, inclusive (R-35); T is
   `at_least` / `at_most` / `x` for up / down / either; defaults V4 10 percent, V7 and V10 2 points, `direction` default
   up for V4 and either for V7 and V10 (R-36, R-84). The echoed threshold is the one used (default filled) under its
   own name.
9. `x` of V4, V7, V10 (direction either) is a threshold magnitude, not a percentile: S09 does not type-check it for
   M3A-3, M3A-6, M3A-9 (only `at_least` and `at_most`), so S07 type-checks it like them (int, Fraction, decimal text;
   anything else `malformed_type`, after the S09 codes) and applies NO 0..100 range code. Open question 5.
10. V7 (R-30, R-33). now = iv91 - iv30 (longer minus shorter), the exact difference of the unrounded tenor floats rounded
    once (no float subtraction); gap_change_points = (now - n-th prior) x 100. Both tenors 30 then 91 must be available;
    the first failing tenor is the reason. A frame without tenor 30 or 91 (built without them) is `malformed_type`.
11. V10 (R-27, R-28, R-34, R-135). now = the 30-day skew: the put side and the call side are each brought to 30 days
    by the S04 tenor kernel on the per-expiry 25-delta IVs (an expiry or a side that failed is passed to the kernel as
    unavailable with its reason, which gives R-104, R-139 `no_bracketing_expiry` / `no_delta_bracket` and R-178), then
    put minus call, exact difference rounded once. Failure order: put side, then call side. `prior_kind` default
    "frame", `condition` default "change"; sign_changed = signs of the rounded now and prior differ and neither is 0;
    `sign_change` fires when sign_changed. A frame whose own `delta_convention` echo differs from the request is
    `convention_mismatch` (a frame of the other convention must not be read silently). `priors` is [] for the frame kind
    (D-04: the fixture value has no prior key).
12. Labels (R-105, R-180). Available results carry the labels of the expiries USED (V4 ATM: the nearest eligible expiry;
    V4 30d and V7: `expiries_used` of the tenors; V10: those of both sides), plus "delayed" under a delayed tag;
    unavailable and invalid results carry []. See open question 1 for the source of the per-expiry label.
13. Never raises on caller data: any value the output cannot read (nan, a missing frame key, a non-dict frame) is
    `invalid_input` `malformed_type`; hostile objects are guarded (tests pin it). No hidden state: nothing is kept
    between calls and the store is only read.
14. The result `series_id` is the series read (V7, V10) and null for V4 (no series is read, the prior is an input).

## Open questions for the coordinator (not decided here)
1. Per-expiry model label. R-180 (rows V4-A-15, V4-A-16) needs the label of the ATM legs of the expiry USED, but S05
   keeps it private (`_Expiry.atm_label`); `stats["floats"]` has no label, and the frame `labels` union all expiries and
   25-delta strikes (and are [] for an unavailable frame, which is the usual case for V4 to V7). S07 reads an optional
   `floats["expiries"][days]["label"]` (and, if present, a list `labels` with every label the expiry's items use, which
   V10 would need for mixed-style 25-delta strikes within an expiry). Without it S07 falls back to the frame labels. The
   tests supply the key through a test-local stand-in (`adapt_surface_change.with_labels`, private `_assemble`), as the
   S10 tests did for `floats` before S05 exposed it. Needed before S11: a small S05 patch ("S05d": `fl["label"]`).
2. S10 sign of `term_30_91`. S10 stores `_diff_units(t30, t91)` = iv30 - iv91, while V7 (R-30, fixtures) is the gap
   longer minus shorter, iv91 - iv30 (row V7-A1: now +0.02, tenors 0.22 and 0.24). A session prior read from the
   store would have the opposite sign to `now`. Either S10 stores iv91 - iv30 or V7 negates; no fixture pins the stored
   sign. S07 follows the fixtures for `now` and reads the stored value as is.
3. S10 `skew25` definition. S10 stores the put - call 25-delta skew of the NEAREST ELIGIBLE expiry; V10 `now` is the 30-day
   constant-maturity skew (R-27, R-28; row V10-I1 interpolates 20d and 45d). The prior and `now` differ by definition
   unless the nearest expiry is the 30-day one. A ruling is needed: S10 should store the 30-day CM skew (and skew25_fwd).
4. The frame must be built with the tenors the output reads (V4 30d: 30; V7: 30 and 91; V10: 30). S07 reports a missing
   tenor as `malformed_type`; a ruling may prefer another code.
5. `x` range for the change outputs (item 9) and whether S09 should own the type check of `x` for M3A-3, M3A-6, M3A-9.
6. All 188 rows pass on the first implementation run, the non-gating near-threshold rows included (their `fired` is
   asserted only where the row says `fire_assert`).
