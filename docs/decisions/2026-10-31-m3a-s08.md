# 2026-10-31: M3a S08, history rank outputs V1, V3, V9 (`surface_rank.py`), Developer choices
mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12
Status: Developer choice (S08), for code and architecture review. R-42 to R-58, R-110 to R-114, R-131 item 7, R-143, R-151 to R-160, R-190 to R-195, the IO contract section 4 and the S02b decision (item 7) settle the rules. The following was open; each item says what was chosen. Items 3, 4, 5 and 9 are spec ambiguities for the PO / Architect to confirm.

1. Entry point (author2 D1, never ruled for the code). Three pure functions on the S02 store: `rank_v1`, `rank_v3`, `rank_v9` (`option_features/surface_rank.py`), each `(store, underlying, session, evaluation_ns, now | put25_iv, call25_iv, params=None, upstream_reason=None, labels=("exact-model",), cutoff_ns=None)`. `session` is an M2 `SessionInfo` (session_id, complete, feed_delay_tag are read). `now` is the unrounded binary64 value from the frame (no frame is parsed here); `upstream_reason` carries an unavailable frame value (`no_bracketing_expiry`, `no_atm_strike`, `low_surface_coverage`, a solver reason, ...). `params` is the request dict of the contract (mode, lane, x, tail, min_sessions, max_sessions, minute, iv_form, delta_convention; `feed_delay_tag` in params overrides the session's, as in the S09 request dict). The result is an `m3a_common.Result`. The series id is `<underlying>/<lane>/<metric>`; metric is `iv30_close` (V1), `atm_iv` or `iv30` by `iv_form` (V3), `skew25` or `skew25_fwd` by `delta_convention` (V9). An invalid result carries the series of the requested lane and form when those are valid, else the defaults (rows V3-071..080, V9-058..065 assert `series_id` that way).
2. History path (S02b item 7, R-192). Only `scalar_baseline` (V1, V9) and `same_minute_column` (V3); no `HistoryView`, `baseline`, sorted copy or merged array (tested: `store.baseline` replaced by a function that fails; the two read functions are spied). The read status is checked before any value is used: `invalid_input` is reported as its code (this is request position 17, `convention_mismatch`, and any read code), `unavailable` is `insufficient_history` (values are None and never touched). The read is given the validated `min_sessions`, `max_sessions`, `lane` and `delta_convention`; `x` is not passed (already validated here with the shared S09 rule `m3a_validate.x_value`).
3. Order of the codes in one list (ambiguity: the request list and the view-read list are separate lists in the contract). Chosen: cutoff type / `bad_cutoff`; request position 4 (mode; V3 is intraday only, R-175); 5 (lane); `session_not_in_calendar` (view read position 1, here after position 5 because it needs the session and the calendar); position 10 (type checks in the S09 order: evaluation_ns, feed_delay_tag, tail, min_sessions, max_sessions, the current values, then `cutoff_mismatch`); `invalid_session_window` (view read position 3, after the position-10 types); 13 (iv_form, delta_convention); 15 (x: type first, then range); 16 (minute: type, then range against the CURRENT session's grid, so a half-day bounds its own minute); 17 (`convention_mismatch`, found by the read: a skew-type series whose selected records carry the other convention; the request convention itself cannot mismatch because the series is chosen by it); 18 (`delayed_feed_tag`). All fixture pair rows follow (V3-036, 037, 077..080; V9-065..069). Structural codes always come before any evaluation (R-131), so the read runs before an upstream reason is reported. The S09 request list and this module give the same code for the same parameters (tested: 6,000 random parameter sets against `validate_request`, empty chain, valid spot and rates).
4. Current V3 value of 0 at the minute (S02b item 7: "unavailable and never ranked"; no reason is ruled and the reason set is closed). Chosen: `unavailable` with the reason the upstream frame value would have had when the grid point is 0: `no_atm_strike` for `iv_form` atm, `no_bracketing_expiry` for 30d (S10 writes a 0 grid point exactly when the minute's ATM or 30-day IV is unavailable). It is checked after the upstream reason and before `insufficient_history`. A scalar 0 (V1, V9) is a real value and is ranked. NEEDS PO CONFIRMATION of the reason.
5. Echo of a rational `x`. Rows V1-040, V3-040, V9-032 (x as a tagged Fraction) expect `params.x == "5/2"`; chosen rule: an int `x` is echoed as given, a Fraction or "a/b" or integer text as the reduced "a/b" text (an int when integral), which is also valid canonical JSON (a Fraction object is not: `m3a_common.canonical_line` has no encoder for it). The default `x` is the int 5.
6. V9 current value. `x` of V9 is the EXACT binary64 difference `put25_iv - call25_iv` rounded once, half to even, to 10^-8 (the rule of the S10 builder, `surface_series._diff_units`), so the current value and the stored `skew25` history are the same quantity (R-48, R-189). `m3a_common.skew_units` rounds the float-subtracted difference and can differ by one unit in rare cases; it is not used here (S06 and S07 should use the same exact rule for their skew points; not changed here).
7. Rank and ties. `rank_le = count(history <= x)` (an int), `upper_share = count(history >= x) / n`, `lower_share = rank_le / n`, shares as an int when 0 or 1 and the reduced "a/b" text otherwise (`m3a_common.ratio_text` rule, tested against it). Top X fires when `upper_share <= X/100`, bottom X when `lower_share <= X/100`, on integers (`ge * 100 * xd <= xn * n`). V3 is top only: it has no `lower_share` and ignores `tail` (type-checked as in S09, not echoed). A constant history is `zero_range_history` (R-46). Reason order for results: upstream and current-zero, `insufficient_history`, `session_not_complete` (mode close only), `zero_range_history` (R-131 item 7).
8. Delay and mode (R-58, R-175). Intraday V1 and V9 and every V3 under a delayed tag: `invalid_input` `delayed_feed_tag` (V3 never has mode close: `invalid_mode`). V1 and V9 with mode close and a delayed tag are computed and labelled `delayed` (sorted with the model label, R-132). Mode close needs a sealed session (`session_not_complete`); intraday does not.
9. Echo on non-available results. An `invalid_input` result carries `params` None (it may hold values that are not valid parameters); unavailable results carry the params echo; `labels` are `[]` unless available (R-105); the `lane` of an invalid result with an invalid lane value is "stock". `min_sessions` / `max_sessions` supplied as None mean the defaults 20 and 252. A `labels` argument that is not a str, None or an iterable of str is `malformed_type`; `underlying` must be a str.
10. Never raises on caller data: hostile `session`, `params`, `now`, labels or underlying give `invalid_input` `malformed_type` (tested with objects whose attribute access raises). `"1/0"` text as `x` is `malformed_type` (the shared S09 rule raises `ZeroDivisionError` for it; caught here, not changed in S09).
11. Rows. 201 rows owned (V1 52, V3 80, V9 69), one test method per row id, all green; the G4 fingerprints (`m3a_g4_histories.json`) are checked by regenerating the planted histories from the ruled seed (calendar hashes, the six planted histories and the constant one) and reading their counts back through the rank outputs. Lane rows: LANE-003..006 are first-owned by S09 and are still skipped in `tests/m3a/test_m3a_validate.py` ("wired here by the lane story"); no S08 row is skipped and D25-V1..V7 are not skipped on main (they pass in S09). Neither file was edited (the plan forbids editing another story's test).

13. Performance. See the PR comment and below for the figures; the design is: one read, one `sorted` of at most 252 ints, two bisects (rank, ties, constant test from the sorted list), one pass of exact-type structural checks, no per-call memo.
