# 2026-10-31: M3a S05c, `stats["floats"]["available"]` (R-197), Developer choices
mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12
Status: Developer choice (S05c), for code and architecture review.

1. Change. `surface_frame(..., stats=...)` now sets `stats["floats"]["available"]` to a real `bool`, `True` exactly when the returned result status is `"available"` (the same condition the Tester used: `res.status == "available"`). It is set after the final reason is known, from the same variable that selects `Result.available` or `Result.unavailable` (`reason is None`), so the flag cannot drift from the status. This is the key S10 (`surface_series`, item 16 of the S10 decision) requires: it stores only when `floats.get("available") is True`.
2. Exact mapping over the S05 status vocabulary (`available`, `unavailable`, `invalid_input`):
   - `available` (no failing expiry, at least one eligible contract, every tenor and 25-delta side available): `True`.
   - `unavailable` (any reason: a failing expiry such as `no_atm_strike` or `low_surface_coverage`, `no_eligible_contract`, a tenor failure, a delta-side failure): `False`. The floats of such a frame may still hold values from its available expiries; the flag makes S10 ignore them.
   - `invalid_input` (malformed input, bad params, early return): `stats` gets no `"floats"` key at all (unchanged), so S10 sees no flag and stores nothing (fail closed). No `partial` status exists in S05.
   - `stats=None`: nothing is written and nothing changes.
3. Nothing else changes: frame text, coverage, labels, params echo, hashes, and the other `floats` keys (`expiries`, `tenors`) and `stats["evaluations"]` are untouched. Proven by a differential test against digests taken on main f8aada1 (item 5).
4. Tests, new file `tests/m3a/test_surfaceframe_available.py` (no edit to hash-pinned fixtures or manifests, which are read only): flag is a bool equal to `status == "available"` on all 595 fixture rows (313 S05-owned author1 rows and the author3 chain rows of v5, v6, v8, v10, v11, v21), with all three statuses seen, at least 3 distinct unavailable reasons all False, unavailable frames that still hold float values are False, no-stats call works; end to end real S05 output (no flag added by the test) through `surface_series.build_records`: records for every available frame, none for any unavailable frame, minute values `(None, None)` for an unavailable frame, and no `skew25_fwd` from an unavailable forward frame (with a positive control).
5. Differential: `tests/m3a/s05c_golden_main.json` holds, per row, the sha256 of the canonical result line plus the floats dict without the new key plus the stats key set, generated on main f8aada1 (a pristine `git archive` copy). The test recomputes on the patched code and requires equality for all 595 rows.
6. Performance (existing W02 workload chain, size M, contract IVs cached, tenors 9/30/91, 30 repeats after one warm-up, frame increment p50): before (main) spot 12.85 ms, forward 12.40 ms with stats=None, 12.80 / 12.86 with stats; after spot 13.54 / 13.43, forward 12.92 / 12.75. The stats=None path is unchanged code and moved by the same amount, so the difference is machine noise; the added work is one dict store per call.
7. Consequence: S11 is unblocked from S05c; it must still never pass a frame without the flag (S10 item 16). `surfaceframe.py` docstring updated for the new key.
8. Stale-flag fix (architecture review). `surface_frame` now does `stats.pop("floats", None)` on entry, before any early return, so a reused `stats` dict never carries a previous call's floats (an `invalid_input` call after an available one leaves no `floats` key). Frame text and the golden digests are unchanged. S11 passes a fresh `stats` per call anyway and never relies on the clearing. Tests: `ReusedStats` (available then invalid_input: no key and no records; available then unavailable: False and no records; hostile params early return clears).
