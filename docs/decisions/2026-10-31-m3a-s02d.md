# M3a S02d: O(1) convention summary for scalar_baseline on skew series (R-193, B5 share)

mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12

Author: Developer, 2026-10-31. Patch story after the S08 measurement (PR 129): `scalar_baseline` on a skew series (skew25, skew25_fwd) scanned the conventions of every selected record (up to 252) on every call; on an attached or loaded store the 252 "spot" / "forward" strings are distinct objects, so each compare cost more than an identity test.

1. Design. `flowstore._Cols` gets one slot `cc`: a dict convention (None, "spot", "forward") -> count of the ring's records. `push` adds the record's convention; `evict` subtracts the evicted record's and deletes the key at zero. Nothing else maintains it, because every other path already goes through these two: the layout is dropped (`ring.m3a = None`) and rebuilt by `m3a_cols` (which pushes every record) on a failed append, a failed seal, an `add_series` k change, `append_many` rollback, and after load, from_snapshot, from_binary_snapshot and attach_binary. `_Ring.__getstate__` is untouched (the layout is not pickled), so pickling rules, canonical text, record sha, content hash and snapshots are unchanged; M2 series have no layout and M2 is untouched.
2. Read. The request's acceptable record conventions `ok` ({None, "spot"} for spot, {x} otherwise, as before) is computed once (`_conv_ok`). `_select` receives `ok`; when `c.cc.keys() - ok` is empty (every record of the ring conforms), no selected record can mismatch, so it returns no per-record conventions and the scan `set(convs) - ok` runs on an empty sequence. When the ring holds any other convention the old behaviour runs unchanged: the conventions of the selected window (complete records only, last `max_sessions`) are returned and scanned, so a non-conforming record outside the window (evicted from it, incomplete, older than max_sessions) still does not cause convention_mismatch. Order of checks is unchanged: the shared S09 rule first (value and the metric's own convention), then the record part before the n < min_sessions test. A convention-free metric still skips the check. The `c.conv` slice is no longer copied on the conforming path. String interning was not needed: the summary replaces the compare.
3. Semantics preserved (differential): same status, reason, code, values, sessions, n for records with differing or None conventions, scalar series without convention, mixed histories after k changes, ring wrap and eviction, incomplete records later sealed, a lane mismatch, and text / binary / snapshot / attach round trips.
4. Tests (`tests/m3a/test_m3a_history_convsummary.py`, 9 tests): summary equals a Counter of the ring's records after append, eviction (key disappears at zero), seal, k change, a failed append (rollback), and each of four load paths; conforming ring returns no record conventions; non-conforming ring still decides by window (forward record outside the window, evicted mismatch, incomplete forward record sealed later); a differential of 1,100 random stores / 40,000+ reads against an independent pure-Python reference written from the ring's records. Failing first: 8 of 9 failed on the old code (all but the pure behavioural one are about the new summary; the differential fails on `cc`). Mutation check, all caught: eviction not decrementing (3 tests fail), zero-count key kept (3), rollback not dropping the layout (1), rebuild skipping the count (7), read skipping the window scan (4).
5. Differential against the old implementation: `tools/m3a_s02d_check.py digest 1800` run on the origin/main source and on this branch: 34,708 reads over 1,800 random stores (pure, mixed and None conventions; k 3 to 40 with mid-life changes; ring wrap; incomplete and sealed records; lane mismatch; text, snapshot, binary and attach round trips with an extra append on the loaded store) gave the identical sha256 of every result (4e26a5a654ee4914ffc5dec869692a74f1f209354b3c5e8bf004556e9749488a).
6. Developer measurements, not gate evidence (`tools/m3a_s02d_check.py bench`: 60 skew names x 252 sessions, store attached from a binary snapshot, layout built, 1 warm-up pass then 30 repeats x 400 calls, fresh process, 5 processes per side; p50 / p95 in us, median of the 30 repeats): before 14.3 / 14.7, 14.3 / 17.2, 15.3 / 17.4, 14.4 / 17.4, 14.4 / 16.1; after 9.1 / 11.1, 10.9 / 11.3, 9.1 / 10.8, 10.2 / 11.2, 9.0 / 9.3 (budget p95 <= 25). The tight loop is warmer than the S08 V9 mix (57.5 us total), so only the saving is comparable: about 5 us p50 and 5 to 6 us p95 per call; V9 re-measurement is the Tester's. Append through the real store, 20 skew series x 2,500 sessions, k 252, best of 7 per run, 3 runs: before 5.15, 4.76, 4.73 us per record; after 4.93, 4.95, 5.23 (within noise; the added cost is one dict update per push).
