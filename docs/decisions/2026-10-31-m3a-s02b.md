# M3a S02b: zero points in a minute series are holes (R-195)

mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12

Author: Developer, 2026-10-31. Follows R-195 (S10 decision file, item 14): a stored 0 in a minute series means "no value at that minute".

1. Store (M3a series only). A dense minute grid may hold zeros in the contiguous int64 block: `HistoryStore.append` no longer routes an M3a grid with a 0 to the sparse form (it takes the shared full index like any dense grid), and `_Cols._place` no longer refuses a text-loaded grid with a 0. The stored values are unchanged (the zero stays at its minute), so the canonical text, record sha, content hash and binary snapshot of a record are the same as before; a sparse-supplied record (`grid_idx`) or a snapshot written sparse still reads record by record and gives the same values. M2 series (MAX_K = 60), `HistoryView`, pickling rules and every M2 byte are untouched.
2. Read (`same_minute_column`, the one minute read in the module). A session whose value at the minute is 0 is not available, exactly like a short grid or an incomplete day: it is not in `sessions`, not in `values`, not in n, and it does not use a window slot. "The LAST `max_sessions` available sessions" therefore means the last non-zero ones, so the window reaches back past holes (a window of 3 over sessions 0..11 with 10 and 11 zero gives sessions 7, 8, 9). Scalar series are unaffected: a scalar 0 is a real value (`scalar_baseline` unchanged, tested).
3. Status. An all-zero column (or fewer non-zero points than `min_sessions`) is `unavailable` with reason `insufficient_history` and `value = {"values": None, "sessions": None, "n": n}` (n = 0 for all-zero). No new code: min_sessions is at least 1, so n = 0 always falls under the existing insufficient-history rule. A zero never produces an invalid_input code.
4. Performance. Fast path unchanged in shape: one strided slice of the block, rotated by `head`; the window is filtered with `filter(None, ...)`, which is the only added work and replaces the plain tuple copy (hole-free reads cost the same). When the window holds a hole, the ids are selected with `compress`, and the window reaches back over the rest of the ring if every earlier row is complete, in the block and long enough; otherwise the record-by-record path runs newest first and stops after `max_sessions` non-zero values. Convention is not copied for convention-free metrics (the check ignores it). No new per-call memo or copy that survives the call (R-193).
5. Tests: `tests/m3a/test_m3a_history_holes.py` (semantics, layout in the block, text and binary round trip with identical content hash, eviction, a differential against an independent pure-Python reference over 20,006 random grids / 16,110 reads including all-zero, single-non-zero, zero at both edges, short, incomplete and sparse-supplied records and rings of k = 1 to 20; the perf smoke). They were written failing first (14 of 17 failed on the old code), then mutation-checked: filter removed, slow path keeping zeros, window trimmed from the wrong end, window off by one, reach-back disabled, reach-back preconditions skipped, append rejecting zeros, `_place` rejecting zeros: all caught (the last was caught only after the text-load layout assertion was added). `test_minute_zero_is_a_value` in test_m3a_history.py is replaced by `test_minute_zero_is_a_hole` (the old expectation was the pre-R-195 rule). Perf asserts are smoke checks via `m3a_harness.best_of`, budgets identical to GATE_BUDGETS sections 5 and 8; they are not gate evidence.
6. Developer measurements, not gate evidence (per call, 30 repeats after 1 warm-up, fresh process, 20 names x 252 sessions x 390 minutes, minute 195, k = 252, max_sessions 252; synthetic workload, relative engineering budget; 3 processes per row; p50 / p95 in us): hole-free 33.8 / 40.6, 33.8 / 47.3, 35.7 / 46.6 (budget p95 <= 75); 1 percent zeros (n = 249) 34.7 / 45.9, 31.2 / 43.9, 31.2 / 39.4; 3 percent (n = 243) 34.9 / 45.6, 37.7 / 46.3, 34.2 / 45.7; 5 percent (n = 237) 34.9 / 46.6, 36.0 / 46.8, 35.9 / 45.7 (budget p50 <= 150); ratio of p50 to the hole-free p50 of the same session 0.92 to 1.06 (budget <= 1.3); scalar_baseline 8.6 / 11.1 and 8.6 / 10.7 (budget p95 <= 25). The same run before the change on a quieter machine moment: hole-free p50 about 25 us. The gate figures (at least 30 repeats, Tester machine) belong to the Tester.
