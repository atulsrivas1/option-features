# 2026-10-30: M3a S10 series builder, Developer choices
mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12
Status: Developer choice (S10), for code and architecture review.
1. R-189 (Architect ruling, option a). R-48 and R-181 stand: stored `skew25`, `skew25_fwd` and `term_30_91` are the difference of the UNROUNDED floats, rounded once, half to even, to 10^-8 integers. Rounding the two sides first would break merged rows M3A-U-010, M3A-U-012 and M3A-V9-036. S05 therefore exposes its unrounded values in `stats["floats"]` ({"expiries": {"<days>": {atm_iv, put25_iv, call25_iv}}, "tenors": {"<t>": float or None}}, keyed like `frame`; None = unavailable). S10 reads only that; it never parses frame text. The S05 patch is a separate PR; S10 tests build the dict with a test-local helper until it merges. `atm_iv_close`, `iv30_close` and the minute grids are each value rounded once. The exact difference is computed in integer arithmetic on `as_integer_ratio()` (no float subtraction, no Fraction object).
2. Which expiry feeds `atm_iv_close`, `atm_iv` (minute grid) and `skew25`/`skew25_fwd`: the nearest eligible expiry (lowest `days` whose `atm_iv` is a finite float), per the IO contract (R-151, R-153). If that expiry's put or call side is None, `skew25` has no value for that session (no fall-back to a farther expiry).
3. An unavailable value gives no stored record for a scalar series (the session is "missing" and `scalar_baseline` skips it, R-51). In a minute grid an unavailable minute is 0 (the M2 dense zero-fill convention). A value that is not a finite float (NaN, inf, bool, str) is treated as unavailable; the builder never raises on caller data.
4. Interface to the store: records are plain tuples `(series_id, metric, window_s, session_id, grid, total)`; `append_records(store, records, lane)` calls `store.append(series_id, metric, 0, session_id, grid, total=total, lane=lane)` (the M2 signature) and returns `(count, code)`; a store exception stops the batch and its `code` is returned. SUPERSEDED by items 7 to 12: S10 now declares `add_series` itself, passes the record convention and validates the batch; its tests also use the real S02 store.
5. (Rounding speed; superseded by item 11 for the guard band.) Grids are rounded as `round(x * 1e8)` in C-level passes, with an exactness check (any fractional part within 0.01 of a tie sends the whole grid to the exact integer path). Result is identical to exact half-even rounding (tested against a Fraction reference on 9,000 values including ties).
6. W08 measurement (R-191; wording superseded by item 12). W08 times building the 7 records from per-series value columns plus the append (store-append throughput, M3A-B6): the gate number uses pre-extracted minute columns (`minute_columns`) and a null store. Extracting minute values from per-minute `stats["floats"]` dicts is runner work counted in G0 (S11), not W08; S11 appends 2 floats per minute (atm_iv, iv30) in its G0 loop and passes the columns. The rule for which value is the minute value is owned here: `minute_values_from_floats(f) -> (atm_iv, iv30)` (nearest eligible expiry ATM IV; tenor 30); the `minute_floats` path calls it. Its cost (about 16,000 to 19,000 records/s through the builder) is printed as informational only. The real store append cost is S02's.
7. Tester round 1, D1 (convention). `append_records` passes `delta_convention` to `store.append` by metric (R-160, S02 item 13): "forward" for `skew25_fwd`, "spot" for `skew25`, None (no field) for the convention-free metrics. A spot record carries the explicit "spot" so a forward read of `skew25` and a spot read of `skew25_fwd` are both `convention_mismatch`, and the field survives a text round trip. Tests use the real `HistoryStore` and read back through `scalar_baseline`.
8. D2 (retention). Before the first append of each series id in a batch, `append_records` calls `add_series(series_id, 252)` unless `k_of(series_id)` is already 252 or more (idempotent, never lowers). Without it a store at the default k keeps 20 sessions. Test: 60 sessions, all 60 retained, for every scalar and both minute series. A store without `add_series` (a fake or null store) is appended to as before.
9. D4 (batch safety; updated in round 2, item I). `append_records` validates the whole batch before the first append, with public store APIs only (`calendar`, `strict_calendar`, `m3a_cols(...)` for the retained sessions, `baseline` for the ring lane) and the earlier records of the same batch: record shape (`malformed_type`), lane of the series id against `lane` (`lane_mismatch`), the lane of an already stored ring (`lane_mismatch`: a one-record `baseline` view of the ring's last complete session in the requested lane exists only when the lane matches), session in the calendar (`session_not_in_calendar`), grid longer than the session (`record_length_mismatch`), session equal to or before the last retained or batched session of that series (`duplicate_session`, `out_of_order_append`), grid and total types and every grid element an exact int, not bool (`malformed_type`). It reports the first failing record in the store's order, appends nothing and returns `(0, code)`. `append_many` is not used (it cannot carry the convention). What is still invisible through public APIs: the lane of a ring whose last record is incomplete, and a store of another kind; the store then raises while appending, the batch stops, and the result is `AppendResult(committed=n, code)` with `partial` True when n is above 0 (never silent). Nothing is rolled back. A retry after a partial commit hits `duplicate_session` on the first record (`(0, "duplicate_session")`); the S11 runner builds a fresh store per run, so it never retries into a used store. A caller exception with an empty message gives its class name as the code. `AppendResult` pickles, copies and deep-copies. The validation mirrors `HistoryStore.append`; drift is gated by `TestValidateDrift` (each category and the precedence when several apply). A store without `calendar` / `m3a_cols` (a fake or null store) is only shape-checked, which keeps the W08 null-store build gate free of store checks. The ring-lane probe builds a one-record `HistoryView` (cached by the store) per stored series; it costs part of the informational end-to-end figure. Second drift case, pinned by a test: when the ring's last stored session is the last calendar session, the ring-lane probe is skipped (`pos + 1 < len(cal.ids)` is false), so for a record of the wrong lane the store says `lane_mismatch` while S10 says `duplicate_session` or `out_of_order_append`; with a strict calendar every such batch is still rejected with count 0 (no later session exists); with a non-strict calendar and a later session the store raises after earlier records were committed and the result is accurate, `(1, 'lane_mismatch')` with `partial` True. The ring-lane probe bumps the store's `view_misses` and leaves a one-record view in the view cache: S08 must not assert on view counters of a store S10 wrote to. `declared=` trusts the caller: S11 calls `declare_series` on the SAME store it appends to, after any load, and passes the returned set.
10. D5. `build_records`, `scalar_units`, `minute_values_from_floats` and `grid_units` catch `Exception` (not `BaseException`) around every read of caller data, so an object whose `__getitem__`, `get`, `items` or `__iter__` raises (for example RuntimeError) gives an unavailable value, never an exception. A column that cannot be iterated gives an empty grid and, since round 2 (item 14), no record.
11. D3 (performance, W08 build rate on random full-precision IV floats). The fast grid path no longer sends about 2 percent of entries to the exact path: the guard band now scales with the data (`_window`) instead of the fixed 0.01, so a random IV column takes the exact path for fewer than 1 in 10^5 entries. The bound and its proof are in the `grid_units` docstring and tests (`GuardBand`): u = fl(fl(v * 1e8) + c) with c = 0.5 + W errs by at most W/4 for |v| < 2^16; an entry with u - floor(u) below 2W (all ties, all near-ties) is rounded exactly, the rest equals exact half-even rounding. The test is one-sided (`min`), uses `math.floor` (negatives need no separate path) and does not build the fraction list unless an entry needs fixing. Outputs are unchanged: an old-versus-new differential (67ba376 against this head) over 27,000 build cases per seed (hostile mixes of nan, inf, huge, -0.0, None, bool, int, str, near-ties, values near 2^16) plus 6,000 grid cases (about one million entries) gave 0 differences (4 seeds). W08 build rate, random full-precision IV floats, null store, 30 fresh processes (p5 / p50 / min, records per second): 32,713 / 34,700 / 30,129 and 32,771 / 35,127 / 31,097 in two runs, against 20,632 / 23,223 / 19,811 for 67ba376 on the same harness (floor 25,000; 15 percent margin is 28,750).
12. W08 scope (R-191 stands; wording amended by R-196, round 2, item F). W08 gates the BUILD of the records (null store) at >= 25,000 records/s, p5, on the mixed workload of item 15. M3A-B6 gates the real-store append (S02). The end-to-end figure (build plus append into the real S02 store) is reported with a hard limit of 5,000 records/s and is informational against 25,000. Steady state on the full store is about 20,000 records/s (build about 33,000/s, S02 append with validation about 49,000/s); a 2-session cold run is about 10,000/s because each ring allocates its k = 252 block on first use. The S11 report carries five figures, each from fresh processes, at least 30 repeats, p5 / p50 / p95 / min: (1) W08 build-only on the mixed workload; (2) B6 append; (3) end-to-end steady state on the full 252-session, 103-name, k = 252 store; (4) the 2-session cold figure, only beside (3); (5) the per-minute cost of `minute_values_from_floats` and its share of G0. No budget is edited. The W08 unit test is a smoke check (`m3a_harness.best_of`, floors unchanged).
13. Round 2, A (mixed grids). `grid_units` no longer drops the whole grid to the exact path when an entry is not a float: an entry that is not a usable float (None, bool, int, str, nan, inf, a float subclass) is 0 in the result, as before, and the rest takes the fast path. A grid of floats and None is rounded in one fused pass (None read as 0.0, which rounds to 0); any other mix is masked once (unusable entries become 0.0 in a copy, the range check and the fast path run on the copy, then the entries are set to 0). The result is bit-identical to `_slow_grid`. A constant guard band serves |v| < 15 (`_fast_small`, W0 = (1.6e9 + 1) * 2^-50, proof in the docstring); the data-dependent band (`_fast`) serves |v| < 2^16; the exact path serves the rest. A 390-entry grid with 3 percent None costs about 1.05 to 1.3 times the all-float grid (it was about 4.5 times). Differential against 67ba376 over four seeds, 27,000 build cases and 6,000 grid cases each (about one million entries per seed, 0, 1, 5, 30 and 100 percent unusable entries, hostile mixes of item 11): 0 differences once the R-194 omission is applied to the old output.
14. Round 2, C and D (R-194, R-195). A minute series whose grid has no available entry in the session (all None or unusable, a column that cannot be iterated, an empty column, or only values that round to 0) gets no record: the session is missing for that series, like a scalar (R-51). In a minute series a stored 0 means "no value at that minute": an IV that rounds to 0 at 10^-8 (below 5e-9) is stored as 0, that is as unavailable. S02b implements the read skip; flowstore is not changed here.
15. Round 2, B (W08 workload). The W08 test workload is random full-precision floats with 1 to 5 percent unavailable minutes per column (seeded; runs and singles; half of the holes in the first 30 minutes) and one fully unavailable iv30 column per 20 names. The 25,000 floor is unchanged and gates on this mixed workload; the all-float rate is printed beside it as information.
16. Round 2, E (R-197), FAIL CLOSED (coordinator ruling, final round). History is written only from an AVAILABLE frame (R-141). The S05 frame status is not in `stats["floats"]` today (it is on the result: `res.status`). S10 stores a record only when `floats.get("available") is True`: a missing key, None, 0, 1, "no", False or any other value stores nothing (no scalar record, no `skew25_fwd` from a forward frame that is not True, and 0 at the frame's minute in the minute grids), and so does a frame whose `get` raises. The key is the named story S05c (`stats["floats"]["available"] = (result.status == "available")`, a separate S05 patch PR), a HARD PREREQUISITE of S11: S11 is blocked by S05c, and S11 never passes an unavailable frame (or any frame) without the flag. `surfaceframe.py` is not edited here. Tests use real S05 output with the flag added by the test, and pin the fail-closed values.
17. Round 2, H. `series_id` returns None (and `build_records` returns []) for an underlying or lane that is empty, not exactly a str, or contains "/": the underlying is the adapter symbol and must not contain "/"; the adapter normalises or rejects before S10. The `grid_units` docstring states the platform assumption (binary64, round to nearest even, no fused multiply-add, no x87 extended precision; verified for CPython 3.12 on Windows x64; re-run GuardBand and Differential elsewhere), and a self-check test pins four `v * 1e8 + c` results that differ under FMA.
18. Round 2, J. Tests pin: nan / int / bool in grids, term without tenor 91, skew with one side, zero-valued scalar records, type pre-checks, lane checks (fresh store, three or more ids, non-strict calendar, non-str lane), `partial` False on success, a non-stock lane, KeyboardInterrupt propagating, hostile objects raising TypeError, ValueError, KeyError, AttributeError and others, and `minute_floats=[]`.
19. Follow-up stories (no code here). S05c: expose `available` in `stats["floats"]` (item 16); S11 is blocked by it. S02b: zero points in the contiguous block and a zero-skip read per R-195; it must merge before S08 merges any rank or percentile read of a minute series (not only before the B5 bench), because holey minute grids stored as zeros distort ranks until the R-195 zero-skip read exists. S02c: an all-or-nothing `append_batch` that carries `delta_convention` (R-198), plus a public `last_session(series_id, metric, window_s, lane=None)` accessor, before M3b and before any non-runner appender; S10 then drops `_validate`. S06: scalar zeros are real values; minute-series zeros mean no value. Briefs: S11 uses `AppendResult.partial`, calls `declare_series` once per store (item 9) and never passes an unavailable frame without the flag. `declare_series(store, ids)` (add_series only for ids below 252; returns the ids at 252 or more) and `append_records(..., declared=None)` let the runner declare once and skip the per-call check.
20. Rulings and the W08 fixture row. R-193 to R-198 are the rulings this story follows: R-193 (derived read state is dropped per call), R-194 (a minute series with no available entry has no record), R-195 (a stored 0 in a minute series means no value), R-196 (W08 gates the build of the records, null store), R-197 (history only from an available frame), R-198 (the all-or-nothing, convention-carrying batch append, S02c).
