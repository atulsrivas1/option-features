# 2026-10-30: M3a S10 series builder, Developer choices

mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12

Status: Developer choice (S10), for code and architecture review.

1. R-189 (Architect ruling, option a). R-48 and R-181 stand: stored `skew25`, `skew25_fwd` and `term_30_91` are the difference of the UNROUNDED floats, rounded once, half to even, to 10^-8 integers. Rounding the two sides first would break merged rows M3A-U-010, M3A-U-012 and M3A-V9-036. S05 therefore exposes its unrounded values in `stats["floats"]` ({"expiries": {"<days>": {atm_iv, put25_iv, call25_iv}}, "tenors": {"<t>": float or None}}, keyed like `frame`; None = unavailable). S10 reads only that; it never parses frame text. The S05 patch is a separate PR; S10 tests build the dict with a test-local helper until it merges. `atm_iv_close`, `iv30_close` and the minute grids are each value rounded once. The exact difference is computed in integer arithmetic on `as_integer_ratio()` (no float subtraction, no Fraction object).
2. Which expiry feeds `atm_iv_close`, `atm_iv` (minute grid) and `skew25`/`skew25_fwd`: the nearest eligible expiry (lowest `days` whose `atm_iv` is a finite float), per the IO contract (R-151, R-153). If that expiry's put or call side is None, `skew25` has no value for that session (no fall-back to a farther expiry).
3. An unavailable value gives no stored record for a scalar series (the session is "missing" and `scalar_baseline` skips it, R-51). In a minute grid an unavailable minute is 0 (the M2 dense zero-fill convention). A value that is not a finite float (NaN, inf, bool, str) is treated as unavailable; the builder never raises on caller data.
4. Interface to the store: records are plain tuples `(series_id, metric, window_s, session_id, grid, total)`; `append_records(store, records, lane)` calls `store.append(series_id, metric, 0, session_id, grid, total=total, lane=lane)` (the M2 signature) and returns `(count, code)`; a store exception stops the batch and its `code` is returned. SUPERSEDED by items 7 to 12: S10 now declares `add_series` itself, passes the record convention and validates the batch; its tests also use the real S02 store.
5. (Rounding speed; superseded by item 11 for the guard band.) Grids are rounded as `round(x * 1e8)` in C-level passes, with an exactness check (any fractional part within 0.01 of a tie sends the whole grid to the exact integer path). Result is identical to exact half-even rounding (tested against a Fraction reference on 9,000 values including ties).
6. W08 measurement (R-191). W08 times building the 7 records from per-series value columns plus the append (store-append throughput, M3A-B6): the gate number uses pre-extracted minute columns (`minute_columns`) and a null store. Extracting minute values from per-minute `stats["floats"]` dicts is runner work counted in G0 (S11), not W08; S11 appends 2 floats per minute (atm_iv, iv30) in its G0 loop and passes the columns. The rule for which value is the minute value is owned here: `minute_values_from_floats(f) -> (atm_iv, iv30)` (nearest eligible expiry ATM IV; tenor 30); the `minute_floats` path calls it. Its cost (about 16,000 to 19,000 records/s through the builder) is printed as informational only. The real store append cost is S02's.
7. Tester round 1, D1 (convention). `append_records` passes `delta_convention` to `store.append` by metric (R-160, S02 item 13): "forward" for `skew25_fwd`, "spot" for `skew25`, None (no field) for the convention-free metrics. A spot record carries the explicit "spot" so a forward read of `skew25` and a spot read of `skew25_fwd` are both `convention_mismatch`, and the field survives a text round trip. Tests use the real `HistoryStore` and read back through `scalar_baseline`.
8. D2 (retention). Before the first append of each series id in a batch, `append_records` calls `add_series(series_id, 252)` unless `k_of(series_id)` is already 252 or more (idempotent, never lowers). Without it a store at the default k keeps 20 sessions. Test: 60 sessions, all 60 retained, for every scalar and both minute series. A store without `add_series` (a fake or null store) is appended to as before.
9. D4 (batch safety). `append_records` validates the whole batch before the first append, with public store APIs only (`calendar`, `strict_calendar`, `m3a_cols(...).ids` for the retained sessions of a ring) and the earlier records of the same batch: record shape (`malformed_type`), lane of the series id against `lane` (`lane_mismatch`), session in the calendar (`session_not_in_calendar`), grid longer than the session (`record_length_mismatch`), session equal to or before the last retained or batched session of that series (`duplicate_session`, `out_of_order_append`), grid and total types. It reports the first failing record in the store's order, appends nothing and returns `(0, code)`. `append_many` is not used (it cannot carry the convention). The ring lane of an existing store ring is not visible through a public API, so a lane clash with an already stored ring, and a non-integer grid value, are only found by the store while appending: the batch stops there and the result is `AppendResult(committed=n, code)` with `partial` True when n is above 0 (never silent). Nothing is rolled back. A retry after a partial commit hits `duplicate_session` on the first record (`(0, "duplicate_session")`); the S11 runner builds a fresh store per run, so it never retries into a used store. Tests inject duplicate and out-of-order records at record j for j = 0 to 6 and a lane clash at j = 0 to 6.
10. D5. `build_records`, `scalar_units`, `minute_values_from_floats` and `grid_units` catch `Exception` (not `BaseException`) around every read of caller data, so an object whose `__getitem__`, `get`, `items` or `__iter__` raises (for example RuntimeError) gives an unavailable value, never an exception. A column that cannot be iterated gives an empty grid record, as `grid_units(None)` already did.
11. D3 (performance, W08 build rate on random full-precision IV floats). The fast grid path no longer sends about 2 percent of entries to the exact path: the guard band now scales with the data (`_window`) instead of the fixed 0.01, so a random IV column takes the exact path for fewer than 1 in 10^5 entries. The bound and its proof are in the `grid_units` docstring and tests (`GuardBand`): u = fl(fl(v * 1e8) + c) with c = 0.5 + W errs by at most W/4 for |v| < 2^16; an entry with u - floor(u) below 2W (all ties, all near-ties) is rounded exactly, the rest equals exact half-even rounding. The test is one-sided (`min`), uses `math.floor` (negatives need no separate path) and does not build the fraction list unless an entry needs fixing. Outputs are unchanged: an old-versus-new differential (67ba376 against this head) over 27,000 build cases per seed (hostile mixes of nan, inf, huge, -0.0, None, bool, int, str, near-ties, values near 2^16) plus 6,000 grid cases (about one million entries) gave 0 differences (4 seeds). W08 build rate, random full-precision IV floats, null store, 30 fresh processes (p5 / p50 / min, records per second): 32,713 / 34,700 / 30,129 and 32,771 / 35,127 / 31,097 in two runs, against 20,632 / 23,223 / 19,811 for 67ba376 on the same harness (floor 25,000; 15 percent margin is 28,750).
12. W08 scope (R-191 stands). The W08 unit test now builds from random full-precision columns (a different column per name and session; smooth data had hidden the exact-path share), appends to a NULL store, and keeps the best of up to 3 attempts of 30 repeats (floors unchanged; TODO to switch to `m3a_harness.best_of` after PR 123). W08 gates the build only. The end-to-end figure (build plus append into the real S02 store) is printed as informational: about 20,000 records/s in steady state (build about 33,000/s, S02 append with validation about 49,000/s); a 2-session cold run is about 10,000/s because each ring allocates its k = 252 block on first use. That is below 25,000, so per R-191 it goes back to PO and Architect; no budget is edited here.
