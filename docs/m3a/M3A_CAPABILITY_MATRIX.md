mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12

Author: Architect, 2026-10-30 (revision 2 after the independent review of PR 101). Status: DRAFT for PO decision; nothing here is ruled except where a line says RULED (PO rulings from the review). Every PROPOSED item points to M3A_RULING_LIST.md (one batch, RECOMMENDED rulings, so the PO rules everything in one pass before any fixture author starts). Companions: M3A_GATE_BUDGETS.md, M3A_FIXTURE_REQUIREMENTS.md, M3A_RULING_LIST.md, M3A_IO_CONTRACT.md. Baseline: docs/m2/* (matrix, budgets, fixtures, I/O contract, store API), docs/M1_CLOSE.md, the M1 code interface (`chainiv.py`, `quotes.py`, `model.py`).

Sources of truth: design text volatility-radar.md (V rows, sections 2.3 to 2.10, 14), option-contracts.md (gates), audits/workers-vs-conditions.md (audit only), PO release plan V3 (M3 row), docs/FEATURE_STATUS.md (rows), docs/FLOW_NAMING_MAP.md (vocabulary), docs/m2/M2_STORE_API.md (store).

Owner main goal: performance. Every M3a output is a pure, batched function over ONE chain at ONE cutoff plus read-only history views; contract IVs are solved once (M1 `IVChain`, certified solver unchanged) and reused by every output; history is read through the M2 store; the opt-in, default single-process runner (tools/m1_runner) supplies the cores; no result byte depends on worker count. All features first on synthetic data; adapter work only in RQ.

## 2. Legend and assumptions
Client = could run on a bring-your-own-key host if a provider supplies the data; Server = needs a full chain or history a single key will not supply; kernels are Either (pure, D4). Availability: FULL, DEGRADED, UNAVAILABLE (reason from the closed set, section 5). No silent fallback between sources; values from different sources are never merged. Data per the project data-sources assumption: mock/synthetic chains and calendars generated by the Tester; vendor-style, FMP and public columns are shape only ("applies at RQ"). IV is modeled; labels are the M1 vocabulary verbatim: "exact-model" and "approximate: European model on an American-style contract"; a result carries a `labels` list (the model label, plus "delayed" when applicable).

## 3. Matrix
Feed = vendor-style option quote feed (mock until RQ). "IV frame" = one chain (both rights, all expiries), spot, rate, dividend yield at one cutoff, in the exact M1 `IVChain` input record (`ChainContract`: contract_id, expiry_days integer >= 1, right, strike, bid, ask, event_ns, known_at_ns, style, condition). All outputs are batched over names and expiries. V3 and V4 implement BOTH forms of the design ("ATM or constant 30-day"), selected by the request `iv_form` in {atm, 30d}, default atm (R-151 to R-154, OWNER DECISION 2 (2026-10-30, overrides the earlier 30-day-only recommendation)): the ATM form is the M1 `atm_iv` of the NEAREST ELIGIBLE expiry (M1 definition: the strike nearest the forward, ties to the lower strike, mean of call and put IV; eligible expiry = expiry_days >= 1 and covered per R-20 and R-103; the per-expiry ATM IVs stay in the frame); the 30d form is the M1 `iv_30d` (design key constant_30d_iv_change). The design worker all-strike mean within 7 days is a recorded known difference.

## 5. Closed reason set and status
Statuses: available, unavailable (reason), invalid_input (structural code). The set is closed; a new reason needs a PO ruling. Existing vocabulary is reused:
| Reason | Origin | Meaning |
|---|---|---|
| no_atm_strike | M1 | no strike eligible for both rights near the forward |
| no_bracketing_expiry | M1 | a tenor has no bracketing expiry (or a bracketing expiry lacks an ATM strike); no extrapolation |
| price_out_of_bounds, upper_asymptote, sigma_cap, precision_exhausted, bound_precision, iteration_budget | M1 solver | solver failures reused verbatim; propagate from the contract or leg |
| insufficient_history | M2 | fewer than min_sessions available prior sessions, including none stored (design "new") |
| session_not_complete | M2 | close-mode form before the session is sealed |
| zero_denominator | M2 | a ratio or percent-change denominator is 0 |
| no_eligible_contract | new (R-106) | no contract passes the M1 gates, including an empty chain; the frame is unavailable |
| no_delta_bracket | new | the 25-delta target is not bracketed by two eligible strikes of that right; no extrapolation |
| low_surface_coverage | new | the expiry lacks the minimum eligible strikes or coverage |
| fewer_than_two_expiries | new | V6 needs two eligible expiries (not no_bracketing_expiry) |
| no_prior_reading | new | a change or sign change was asked and no prior reading exists |
| zero_range_history | new (design VR P3) | the history has zero range, so a percentile is undefined |
`insufficient_window` is not used (V3 uses the explicit `minute`). Per-contract M1 gate reasons (no_quote, excluded_condition, invalid_quote, crossed_market, locked_market, stale_quote, american_itm, style_unknown) are not surface reasons: they exclude a contract and are counted per reason in `coverage.contract_reasons`. Structural codes (including the value code `cutoff_mismatch`: evaluation_ns differs from the chain cutoff_ns, R-100) and the precedence lists are in M3A_IO_CONTRACT.md. Fixtures assert reason and status.
DELIBERATE exceptions to earlier rulings (stated, each with its source): (1) `scalar_baseline` skips missing and incomplete days and needs only min_sessions available sessions, an exception to M2 Q3 and AMB-17, because the design says "at least 20 prior sessions" (R-51, owner-decided (final): partial history is allowed, missing days skipped, at least 20 prior sessions required); (2) a constant (zero-range) history is unavailable `zero_range_history` (design VR P3), an exception to M2 Q2 where it is available and cannot fire (R-46, owner-decided (final)); (3) a delayed feed gives invalid_input `delayed_feed_tag` where the design says "unavailable", the same interim choice as M2 (R-58, PO interim, not owner-decided). R-81 (30-day form only) is SUPERSEDED by R-151: V3 and V4 implement both forms, so there are three deliberate exceptions (R-46 and R-51 owner-decided (final), R-58 PO interim), each with reason rows. V21 (R-01, owner-decided (final)) is included; V3 and V4 both forms (R-151 to R-154) and both delta conventions (R-155 to R-161) are owner-decided (final).

## 6. Store changes (M2 store, RULED; M2 behaviour unchanged by default)
- M3a series: scalar per-session series atm_iv_close, iv30_close, skew25, term_30_91 and the minute series atm_iv and iv30 (R-153). The scalar series: stored in the M2 store with per-series retention `k = 252`. M2 store facts: `HistoryStore(calendar, k=20)` has default k 20 and a hard cap of 60 (k in 1 to 60); M3a needs k = 252, which EXCEEDS the M2 cap, so M3a raises the hard cap for scalar series (per-series k up to 252) as a DELIBERATE, additive M2 store change: M2 series keep k <= 60 and their behaviour; the store budget is 768 MB (RULED) with the 1 GB hard limit per worker unchanged, stated in M3A_GATE_BUDGETS.md (M3A-B8), the scalar in `total`, `window_s = 0`, grid empty. Values are integers in units of 10^-8 (the rounded-once 8-decimal value, R-48). The V3 series are the two minute grids (dense, window_s = 0): `atm_iv` (nearest-eligible-expiry ATM IV) and `iv30` (30-day IV); the V3 and V4 history and priors are read from the metric of the selected `iv_form`.
- New read forms: `scalar_baseline(series, as_of, min_sessions=20, max_sessions=252)`: available complete sessions before `as_of`, missing or incomplete days skipped (deliberate exception above), no zero-padding; `same_minute_column(series, as_of, minute, ...)`: the value at minute index m of each prior session, sessions lacking m skipped.
- Lane is carried by the series id (ring lane "stock" unless `load(lane=...)`); a history lane differing from the request lane is `lane_mismatch`.
- Memory against the M2 formula (series x K x grid x 8 bytes x copies), restated for owner decision 2: there are TWO minute series per name (atm_iv and iv30): 2 x 103 x 252 x 390 x 8 B = 162 MB raw; with the M2 layout (raw, sorted copy, merged array) 3 copies = 486 MB. RULED 2026-10-30 (PO): the M3a store budget is 768 MB with the hard limit unchanged at 1 GB per worker; bytes per series are reported; sorted copies are built lazily and not for scalar or minute-series reads that do not need them (a Developer design duty); the gate measures private bytes. `same_minute_column` needs no sorted copy, so the copies are skipped for it (about 162 MB). Scalar series are 252 integers each (5 per name, about 1 MB).
