# M2 input and output contract (draft)

mock-data qualification only: passed on independently authored synthetic fixtures and synthetic workloads, Windows x64, CPython 3.12

Author: Architect, 2026-10-29. Status: DRAFT for the Tester and the Developer to author inputs and read outputs against; the exact module names and wire exposure stay open (candidate16 item). Shapes only; semantics are in M2_CAPABILITY_MATRIX.md. Pure functions, no I/O, no clocks, single-threaded kernels. All money and ratios are exact (integer ticks, `Fraction`); no float.

## 1. Conventions
- Times: integer nanoseconds since the Unix epoch (UTC) for prints; windows are closed [T-W, T]; session times are session-relative seconds on the grid.
- Prices: integer ticks (price x 10^4 as in `quotehist.as_ticks`) or decimal strings converted once at ingest; premium = ticks x size x multiplier, exact.
- Text files: UTF-8, LF, canonical key order, no absolute paths. Every dataset has `"provenance": "SYNTHETIC"`.

## 2. Inputs
| Record | Fields | Notes |
|---|---|---|
| Print | `contract_id`, `time_ns`, `price`, `size` (int >= 0), `multiplier` (int, 100 standard), `condition_excluded` (bool), `seq` (int tie breaker) | sorted by (time_ns, seq); `contract_id` resolves to Contract |
| Contract | `contract_id`, `underlying`, `right` ("C" or "P"), `strike` (ticks), `expiry` (civil date), `lane` ("stock" or "etf_index") | lane never mixed in shares or baselines |
| Session | `session_id` (civil date), `underlying`, `open_ns`, `close_ns`, `minutes` (grid length: 390 full, fewer for half-days), `complete` (bool), `feed_delay_tag` ("live" or "delayed") | calendar supplies `minutes`; delay is an input tag set by the adapter, never read by a kernel from a clock |
| Grid (derived) | per series, session, metric: array of `minutes` values at 60 s steps from open; session total | built from prints (M2-B18); sparse form for contract series: list of (index, value) plus zero count |
| HistoryRecord | `series_id` (contract id or name), `metric`, `session_id`, `window_s`, `grid`, `total`, `complete`, `content_sha256` | metrics: premium, contracts, prints, put_volume, call_volume |
| HistoryView | immutable, hashable; the K complete sessions strictly before a given session, per series | reads only; no look-ahead |
| Calendar | ordered list of session ids with `minutes` | the 20-session window is taken from this list |
| Request | `evaluation_ns` (T), `window_s` (60, 300, 900, 1800, 3600; F17 fixed 300), parameters of matrix section 3 (N, X, thresholds, K, minimum sessions, `quiet_gap` default 1), `filter` ("all", "calls", "puts"), `lane` | every parameter value used is echoed in the result |
Structural errors (status invalid_input, `code`): `unordered_prints`, `negative_size_or_price`, `bad_multiplier`, `duplicate_session`, `non_monotone_grid`, `session_not_in_calendar`, `window_not_allowed`, `unknown_contract`, `malformed_type`, `grid_not_60s`, `lane_mismatch`, `record_length_mismatch`, `threshold_required`, `out_of_order_append`, `delayed_feed_tag`, `snapshot_bad_magic`, `snapshot_length_mismatch`, `snapshot_hash_mismatch`, `trailer_missing`, `trailer_count_mismatch`, `trailer_hash_mismatch` (the single status word everywhere: invalid_input with this code; F1, F12, intraday F2 and intraday F10 under a delayed tag). Validation scope: full on build and at the store boundary, scanned on hot paths with an explicit `validate="full"` switch, as for OC5 and OC6.

## 3. Outputs
One result per (output id, series or name, evaluation). Fields in canonical order:
`output_id` (M2-1 to M2-11), `series_id`, `session_id`, `evaluation_ns`, `status` ("available", "unavailable", "invalid_input"), `reason` (closed set below, or null); an unavailable or invalid_input result carries `value` null and `fired` null, `code` (structural, or null), `value` (object of exact rationals as "n/d" strings or integers; per output below), `fired` (bool or null), `params` (every parameter used), `coverage` (counts: eligible_count, nonstandard_count, excluded_condition_count, unavailable_points), `label` (statistic or side name), `lane`, `version`.
| Output | `value` keys |
|---|---|
| M2-1 F1 | `p60`, `p900`, `ratio` |
| M2-2 F2a to F2c | `x`, `n`, `rank_le`, `upper_share`, `form` ("intraday" or "end_of_day"), metric name |
| M2-3 F2d | `parts` (three percentiles = 1 - upper_share), `average`, `direction` ("higher_is_more_unusual") |
| M2-4 F4 | `large_count`, `large_premium` (ticks), `threshold_ticks` (in `params`, 1000000000 for 100,000 USD) |
| M2-5 F17 | `window_premium` |
| M2-6 F7 | `top_strike`, `strike_share`, `top_expiry`, `expiry_share`, `total_premium` |
| M2-7, M2-8 F10, F20 | `x`, `median`, `mean`, `per_statistic` ({median, mean} each with status, reason, ratio), `consumer_default` ("median" or "mean"); top-level `value` is null when the default statistic is unavailable |
| M2-9 F18 (params `at_least`, `at_most`) | `put_volume`, `call_volume`, `put_share`, `put_call_ratio` |
| M2-10 F19 | `ratio`, `n`, `rank_le`, `upper_share` |
| M2-11 F12 | `episode_count`, `first_ns`, `last_ns`, `peak_ratio`, `peak_ns`, `quiet_gap` |
Reason closed set: `insufficient_history`, `session_not_complete`, `insufficient_window` (F1, F2, F10, F12: before session open + W), `zero_denominator`. Mapping to the existing vocabulary (no new synonyms): statistic equal to 0 -> `zero_denominator`; nothing stored or fewer sessions -> `insufficient_history`; `zero_mad` unused. Gate order: invalid_input, insufficient_history, session_not_complete, insufficient_window, zero_denominator.

## 4. Canonical serialization and hashing
- One JSON object per result, keys in the order of section 3, separators `,` and `:` (no spaces), rationals as reduced "n/d" strings (integers as plain integers), booleans and null as JSON, one object per line, LF.
- Results are ordered by (output_id, series_id, session_id, evaluation_ns) - never by completion order. Per-unit SHA-256 over the unit bytes; run hash over `unit key LF unit sha256 LF` in key order (as the M1 runner).
- The store serializes as one line per HistoryRecord in (series_id, metric, window_s, session_id) order, grids as integer lists; `content_sha256` covers the canonical line. Round trip must reproduce the same bytes (M2-B17).
- Worker count, timings, cache statistics and store hashes appear only in the run log, never in results.

## 5. Runner interface (unchanged defaults)
Unit = underlying x session x cutoff (key `SYN1/03/045`); the unit reads an immutable HistoryView as of its session. Opt-in process pool, default single-process; `--workers 1` is the reference path; cap per the PR 72 ruling. The runner adds no calculation.

## 6. PO-M2-AMB rulings: shapes (interim pending design ratification where the design is silent)
1. Print is the wire encoding of the section 2 Print fields, `[contract_id, time_ns, price, size, multiplier, condition_excluded, seq]` plus an optional 8th element `side` (vocabulary "ask", "bid", "unknown"); kernels ignore it.
2. Premium values are integer ticks = price(ticks, 10^4) x size x multiplier. Thresholds are carried as `params.threshold_ticks` (100,000 USD = 1000000000); `value.large_premium` and `window_premium` are ticks.
3. F10 and F20 results: top-level `status`, `reason`, `fired` and `value` follow the consumer default statistic (F10 median, F20 mean); `value.per_statistic` = {"median": {status, reason, ratio}, "mean": {status, reason, ratio}}; `value` is null when the default is unavailable.
4. Grid: point i at open + 60 s x i (i from 0); for a window W the first W/60 points of each session are dropped before open + W; history n counts only the remaining points.
5. F12 `value`: `episode_count`, `first_ns` and `last_ns` (onsets of the first and last episode, null at count 0), `peak_ratio`, `peak_ns` (over the session to date, ties earliest), `unavailable_points` (every unavailable grid point), `quiet_gap`. Before 900 s since open: unavailable, insufficient_window.
6. Store record key (series_id, metric, session_id, window_s); each grid entry is the window-W value of that request window at that grid point. The ring lane of a series is the lane of its first append; `load(lane=...)` overrides it for loaded rings. Canonical line key order: `series_id`, `metric`, `session_id`, `window_s`, `grid`, [`grid_idx`: sparse records only, right after `grid`], `total`, `complete`, `content_sha256`. `content_sha256` = SHA-256 of the canonical line without the `content_sha256` field, followed by LF. Sealing marks a record immutable and builds its sorted copies; an append whose session equals the series last appended session is structural `duplicate_session`; an earlier one is structural `out_of_order_append`. The retention ring counts every stored session, complete or not; history n counts only complete sessions.
7. `label` contents: F1 the filter name ("all", "calls", "puts"); F10 and F20 the consumer default statistic name; F18 "put"; F2 end-of-day under a delayed tag "delayed"; `coverage.degraded` true when F20 uses supplied end-of-day totals. `coverage.excluded_condition_count` counts every print with an excluded condition (including those also nonstandard); `coverage.nonstandard_count` counts only non-excluded nonstandard prints.
8. F2c intraday: x = count / (W/60), history counts divided by the same; F2c end-of-day: x = count / session minutes, history counts divided by the same, windowless for window_not_allowed. F2d: `fired` null, `parts` always shown, `reason` that of the first unavailable part (order F2a, F2b, F2c). F19: fires when upper_share <= X/100, X default 5, n = usable prior ratios (20).
9. Structural error precedence and the unknown_contract, malformed_type, lane_mismatch and record_length_mismatch codes: see section 9 (the single authoritative list). A missing, incomplete or absent session is never structural: insufficient_history, no substitution.
10. `window_not_allowed` applies to F2 intraday, F2d, F4, F7, F10 and F18 (allowed set 60, 300, 900, 1800, 3600 s); F17 is fixed 300 s; F1 and F12 take no window. F18 with neither `at_least` nor `at_most`: `threshold_required`.
11. Defaults: F1 N = 3; F12 ratio N = 3 and n_episodes = 1; F4 N = 1; F10 and F20 N = 2; F2 and F19 X = 5; F7 share 3/5.

## 7. Conventions ruled after the PR 76 review (interim pending design ratification where the design is silent)
- An unavailable result carries `coverage` and `label` only for zero_denominator; for every other gate they are null. F10 and F20 unavailable results carry `label` and `per_statistic`.
- `unavailable_points` (F12) counts every unavailable grid point, including the first 15 before 900 s.
- A history lane differing from the request lane gives insufficient_history. session_not_in_calendar applies to the current session only.
- F12 `peak_ratio` and `peak_ns` are taken over the available points of the session to date even with zero episodes (ties earliest: peak 1 at the earliest available point when all ratios are 1).
- F2d `fired` is null in M2 (design request DR-M2-1, matrix section 11).


## 9. M2-GRID, structural codes, store I/O and runner rules (ratified interim, pending design ratification where the design is silent)
Single authoritative section: every ruling below lives only here. PR 79 section 8 content merges into this section when PR 79 lands; until then PR 79 drops any text that duplicates this section. Rows are authority: the accepted correctness rows and the fixture additions (add_grid, add_struct, add_data).
1. M2-GRID (trade-to-grid builder). Grid point i, i = 0 to minutes-1, is at t_i = open + 60 s x i and holds the metric over the closed window [t_i - W, t_i] of eligible session prints of the lane and series. Dense `value`: {`form`: "dense", `grid`, `total`, `valid_from`: W/60}. Sparse (a contract series, `params.contract_id`): {`form`: "sparse", `sparse`: [[i, v], ...], `zero_count` = minutes minus the number of nonzero points, `total`, `valid_from`}. `valid_from` may exceed the grid (W = 3600 on a 12-minute session gives 60: all points are dropped and history gives insufficient_history). Coverage: `eligible_count`, `nonstandard_count` (non-excluded), `excluded_condition_count` over [open, close] for the lane and series, and `unavailable_points` 0. Metrics: premium, contracts, prints, put_volume, call_volume.
2. Session edges. Session prints are those in [open, close]; a print exactly at close counts toward the session total but toward no grid point; prints after close are excluded. The final minute (close - 60 s, close] holds no grid point, so it is absent from the STORED history grid only; today's windowed value is read directly at any cutoff and includes final-minute prints (Q15). The accepted rows stand.
3. Pre-open clipping is unconditional: windows are clipped at session open, and `open_ns` comes from the request session (rows DAT-001 to DAT-008 pin the clipped results). F1, F2, F10 and F12 keep their availability rule (insufficient_window before open + W).
4. Prices. Text grammar (ASCII): `-?(\d+(\.\d*)?|\.\d+)`; "1." and ".5" are valid; trailing zeros are accepted; a non-zero digit beyond the 4th decimal is `malformed_type`. An integer non-bool price is ticks (dollars x 10^4); text "1.0000" is 10000 ticks; premium = ticks x size x multiplier. A float or bool price is `malformed_type`; a size, multiplier, time or seq that is not an int (bool excluded) is `malformed_type`; `condition_excluded` accepts a bool or the integers 0 and 1, any other value (2, 3, a string) is `malformed_type`; a float `window_s` is `window_not_allowed`. Parameter-level rule: rational-valued parameters (N, shares) accept an int or an exact rational given as an "a/b" string or a Fraction; ticks-valued parameters (threshold_ticks, ticks) accept a non-bool int only; quiet_gap and n_episodes accept a non-bool int only; a float, bool or any other type for any of them is `malformed_type`; a grid step other than 60 s carries the code `grid_not_60s` (parameter-level type and range errors carry the code `malformed_type`); quiet_gap and n_episodes below 1 are `malformed_type` (lower bound 1); both sit at the malformed_type slot of the precedence list (after unknown_contract).
5. Structural precedence (the first failing code is reported; all accepted rows are consistent with it; every accepted store row is a single-error row, so no row fixes an order between codes and no conflict exists). Request and record-set checks: unordered_prints, negative_size_or_price, bad_multiplier, unknown_contract, malformed_type (incl. grid_not_60s), duplicate_session, non_monotone_grid, session_not_in_calendar, window_not_allowed, threshold_required, delayed_feed_tag. Store-append checks (RULED order; it differs from the request-level order above because it is restricted to the checks an append can raise): lane_mismatch, session_not_in_calendar, record_length_mismatch, non_monotone_grid, duplicate_session, out_of_order_append. Snapshot load checks: snapshot_bad_magic, snapshot_length_mismatch, snapshot_hash_mismatch. Text load checks: trailer_missing, trailer_count_mismatch, trailer_hash_mismatch (after the lines parse). `unknown_contract`: print contract_id not in the contracts map. `session_not_in_calendar` applies to the current session only.
6. Store append record. It carries a `lane` field. `lane_mismatch`: the record lane differs from the series ring lane. `record_length_mismatch`: a dense grid longer than the session minutes, or a sparse index outside [0, minutes). A dense grid shorter than the minutes is zero-padded at the end AT READ time, not in the canonical form (rows STORE-005, STORE-033 and STORE-034 stand). The canonical store line carries the grid as supplied (no padding); a sparse record canonical line includes its `grid_idx` list, so equal values at different indices hash differently (the affected row is M2A-STORE-006 in the additions, regenerated by the fixture author). Store ops shape: key `store_ops`; `lane` is optional, default "stock"; the ring lane is the lane of the first append; `load(lane=...)` overrides the lane of loaded rings. `load` takes `lane=` and `strict_calendar` (default True).
7. Snapshot and dump. Snapshot = magic "M2SNAP1" (7 bytes) + total length (8-byte little-endian unsigned: the number of bytes of the whole snapshot) + SHA-256 of the body (32 bytes) + body; body = the canonical store lines, the same bytes as the dump text without its trailer. `from_snapshot` raises, each a structural error with a closed code: `snapshot_bad_magic` (first 7 bytes differ), `snapshot_length_mismatch` (stored length differs from the actual byte count, including truncation), `snapshot_hash_mismatch` (SHA-256 of the body differs). Text dump = canonical lines in canonical order, then the trailer line `#END records=N content_sha256=<hex>` (N = record count, hex = `content_hash()` of the store, lowercase). `load` raises `trailer_missing` (no trailer line), `trailer_count_mismatch` (N differs from the parsed record count) or `trailer_hash_mismatch` (hex differs from the content hash of the loaded records). `content_hash()` = the fixtures' `content_sha256_digest` of the store; `dump_sha256` = SHA-256 of the dump text including every LF but WITHOUT the trailer line (merged store rows pin it); the trailer is appended after the hashed text and verified separately by `load`.
8. F18 carries the top-level key `ratio_reason` only when it is non-null (the key is omitted otherwise); it is `zero_denominator` when put_call_ratio is unavailable because call volume is zero while the status stays available. Every result carries `version` "0.2.0a1" (one fixture row asserts it).
9. F12. Built from prints: coverage counts the lane prints in [open, T] and `unavailable_points` counts every unavailable grid point; built from supplied points, missing points are zeros; grid points before 900 s are unavailable even if supplied.
10. Runner rules: `gc.freeze()` after the store load; compare `content_hash()` after attach; the store memory limit (512 MB budget, 1 GB hard per worker) is enforced by the runner and a store above 512 MB is reported.
11. Binary mmap snapshot (RATIFIED, optional, implementation-private; the production worker-start transfer form beside the canonical M2SNAP1 text format, which remains the persistence and interchange format). Header: name "M2BIN" (5 bytes), format version (2 bytes, little-endian, 1), total file length (8 bytes), SHA-256 of everything after the header digest (32 bytes), then the record table length (8 bytes), the table and the aligned typed arrays; the full layout is in docs/m2/M2_STORE_API.md. The reader maps the file read-only, verifies name and version (`snapshot_bad_magic`), length (`snapshot_length_mismatch`) and SHA-256 (`snapshot_hash_mismatch`) at attach and compares `content_hash()` with the expected value after attach. Gate rule at N = 6,000 series: the HARD limits (15 s start, 1 GB per worker) are the gate and the 5 s and 512 MB budgets are reported targets; at N = 2,000 the budgets are the gate. Private bytes and shared mapped bytes are reported separately (shared file-backed pages count once across workers; per-worker private bytes is the B13 and B16 figure).
